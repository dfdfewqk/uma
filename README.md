# Uma Trainer KR — R31 Portable-first

한국 우마무스메 PC 육성 보조 도구 연구·개발 프로젝트.

## 설치 없이 사용하기

GitHub **Actions → Build Windows portable (installer optional, manual only)**에서 Windows 수동 빌드가 성공하면 `UmaTrainerKR-R31-Windows-Verified`라는 Artifacts를 받을 수 있습니다. 내부 `portable/UmaTrainerKR-Portable-v0.31.1.zip`을 압축 해제한 뒤 `UmaTrainerKR_Companion.exe`를 실행하세요. **설치 프로그램과 Python 설치가 필요하지 않습니다.** 단 OCR용 Tesseract가 별도로 필요할 수 있습니다.

### 이후 버전 업데이트

R31 포터블 도우미는 시작 시와 실행 중 매일 공식 GitHub Release의 안정 버전을 확인합니다. 새 버전이 있으면 **사용자가 동의한 경우에만** 내려받고 SHA-256을 검증하여 새 버전 폴더에 설치합니다. 기존 버전은 삭제하지 않으며 설정/육성 기록은 `%LOCALAPPDATA%\UmaTrainerKR`에 보존됩니다.

GitHub 코드가 변경되었다고 자동으로 실행파일이 업데이트되는 것은 **아닙니다**. 새 **GitHub Release**가 Windows 테스트 후 실제로 게시되어야 새 버전을 받을 수 있습니다. Releases 게시 작업도 수동이고, `publish_release=false`가 기본입니다.

소스 실행: `python -m pip install -r requirements.txt` 이후 `python companion.py`. 전체 테스트: `python -m unittest discover -s tests -q`.

구체적인 사용·릴리스 절차 및 4개월 주기 운영 방침은 [R30 포터블 업데이트 안내](docs/R30_포터블업데이트_사용방법.md)를 확인하세요.

### 기능/검증 범위

- 지원 개발 중: 게임 옆 패널, 훈련 스크린샷 인식 및 검수, 게임 위 추천 표시(Windows 한국 서버 실검증 전).
- R29: 화면 캡처 자료를 **로컬**에서 관리/내보내기. 자동 전송 없음.
- R30: 포터블 버전 조회·검증·별도 폴더 설치·선택적 버전 전환.
- 자동 클릭·완전 자동 육성/실제 게임 기반 ML 학습은 구현되지 않았음.

게임 화면 감지와 OCR 정확도는 실제 한국 서버 환경 테스트 전입니다.

### R31 — 포터블 우선 빌드 변경

수동 `Run workflow`에서 기본값 `build_installer=false`, `publish_release=false`로 실행하면 **Windows EXE 4종·실행 자체검사·포터블 ZIP·SHA256 검증**에 집중합니다. 기존 설치 프로그램 생성/설치/제거 검사는 `build_installer=true`를 명시한 경우에만 실행합니다. 소스 테스트 및 4개 실제 EXE 자체검사는 어떤 옵션에서도 생략되지 않습니다. `publish_release=true`는 검증 완료 시에만 공개 릴리스를 생성하므로 첫 실행은 `false`를 권장합니다.

R31.1의 Windows Actions EXE 자체검사와 시작 모듈 검사는 통과했습니다. 사용자는 Companion GUI가 열리는 것까지 확인했으나, 한국 게임 화면과의 연동/인식 정확도는 여전히 미검증입니다.

### R31 Windows 장시간 대기 방지 패치

기존 Windows 빌드 #2의 EXE 자체검사 구간에 시간제한 없는 `Start-Process -Wait`가 있었다. 이제 `scripts/windows_smoke_r31.ps1`가 개별 EXE·첫 실행 진단에 최대 90초를 적용하고, 설치형 사용 시 설치/제거에도 시간제한을 적용한다. 실패하면 어느 프로그램에서 멈췄는지 표시하고 릴리스 생성은 차단한다. 기존 실행 중인 빌드에는 이 수정이 적용되지 않으므로 **새 Run workflow**로 검사해야 한다. [진단 기록](docs/R31_Windows_빌드_장시간_대기_진단.md)

### R36 분리 검증 (v0.31.2)

8차 Windows 검사에서 4종 실행파일 빌드·자체검사·시작 모듈 검사는 통과했으나 비대화형 Windows 환경에서 전체 GUI 검사만 멈췄습니다. 새 R36 워크플로는 Linux Xvfb에서 **실제 Tk 화면 생성 및 합성 R6→R34→R35 상호작용**을 먼저 확인하고, Windows에서는 실행파일 빌드·패키징을 검사합니다. 가상 화면 검사는 Windows 실물 GUI/한국 서버 검증을 뜻하지 않습니다. [R36 검증 안내](docs/R36_Windows_GUI_빌드검증.md). 새 빌드는 아직 결과 확인 전입니다.

### R37 키보드 없는 Companion 헬퍼 (v0.31.3 · 새 Windows 빌드 대기)

Companion은 실행 시 화면 분석을 자동으로 시작하고 **지금 할 일/화면 상태/OCR 수치 후보**를 보여 줍니다. 사용자는 훈련·휴식·외출·선택지를 게임에서만 클릭하며, 플레이 도중 숫자나 기록을 타이핑하지 않습니다. 개발자 점검·수동 자료 관리는 별도의 접힌 메뉴로 이동했습니다. 분석은 버튼으로 일시 정지/다시 시작할 수 있습니다.

현재 화면의 **R28 검수된 훈련 후보**만 게임 위에 표시할 수 있고, 체력 25 이하 OCR 후보가 연속으로 관측되면 휴식·외출을 *검토하라는 주의*만 표시합니다. **각 훈련/이벤트 효과를 한국 서버 화면에서 자동 검증하고 최적 행동을 추천하는 기능은 아직 미완성**입니다. 이번 단계는 키보드 없는 기본 사용 경험과 상태 관리·검증 경로를 구현했습니다.

새 Windows 포터블 버전은 **0.31.3**이고 기존 **0.31.2 검증 ZIP은 보존**합니다. [구현 범위·제약 및 테스트](docs/R37_키보드없는_헬퍼_전환.md). 새 0.31.3 Windows 빌드는 수동 CI 통과 전까지 미검증입니다.

### R38 레이스·터커 외출 일정 모델 (오프라인 연구 단계)

[턴별 목표 레이스/터커 브라인 외출 판단 설계](docs/R38_레이스일정_터커외출_판단설계.md). 주니어/클래식/시니어 전후반에 따른 **캐릭터·의상별 필수 목표 레이스**와 일본 무인도 SSR 터커 브라인 **1~5회차 회복/다음 턴 효과**를 분리했습니다. 일본 자료의 부가 효과 충돌도 기록했습니다. 실제 육성에서는 게임 화면에서 캐릭터·턴·외출 단계가 확인되어야만 참고 가능하며, 기존 챔미·리오히 4개 외부 대회 일정과 혼동하지 않습니다. **실제 캐릭터별 전체 목표 달력은 0건, 실게임 자동 스캔 연동/최적 행동 추천은 미완료**입니다. R38 코드는 연구 모듈만 추가하며 R37의 검증된 Windows 바이너리/GUI와 기존 R6 점수는 변경하지 않습니다.

### R39 대회·회차·각질 클릭 설정 (v0.31.4 · Windows 새 빌드 대기)

Companion 상단에서 **무인도 / 챔미·리오히 / 1~4회차 / 도주·선행·선입·추입**을 타이핑 없이 선택하며 로컬에 저장합니다. 목표 변경 시 이전 화면의 훈련 증거를 무효화하고 다른 각질로 검수한 R28 추천을 차단합니다.

한국 서버 대회별 정확한 코스 자료는 아직 등록되지 않았습니다(0건). 미검증 코스를 일본 2025 자료로 대체하지 않으며, 코스별 스킬 구매 추천은 **보류**합니다. 향후 거리·각질·마장 스킬 필터, 자동 반복 육성 횟수(도축·실패 포함), 다음 턴 필수 레이스에 의한 버프 무효화 조건은 순수 로직 및 합성 테스트에만 구현했습니다. 실게임 이벤트·스킬 OCR, 완전 자동 육성, 실데이터 ML 학습은 미구현입니다.

소스 사용: python companion.py (기존 R37 기능 유지 + R39 클릭 설정). 수동 CI 빌드 후에만 새로운 EXE를 사용할 수 있습니다. [확정 요구사항·코드 변경·검증 범위](docs/R39_대회설정_통합_검증범위.md).

### R40 소스 전용 개발 — 통합 4회차 정정·자동 육성 준비 (새 실행파일 없음)

R39에서 챔미 1~4회·리오히 1~4회를 따로 고를 수 있었던 오류를 수정했습니다. 현재 무인도에서는 **1회차 챔미 → 2회차 리오히 → 3회차 챔미 → 4회차 챔미**로 단 4개를 한 번에 관리합니다. Companion 시작 설정은 이제 **통합 회차 + 각질** 두 항목이며, 카드/계승은 향후 게임 화면에서 인식할 예정입니다.

기존 R13/R14 일본 2025 대회·한국 일정 조사 자료를 재활용했습니다. 2026년 11월 한국 1회차 챔미 한신 2200m 코스는 GameTora 한국 39회 대회 페이지 및 2026-10-11 한국 가이드를 교차 확인해 **2차 출처 기준**으로 등록했습니다. 공식 공지는 아직 별도 재확인이 필요합니다. 2~4회차 한국 코스는 **미확정**입니다. 일본 코스는 한국 확정 자료로 전용하지 않습니다.

자동 육성 소스 기반에는 반복 N회(도축/실패 포함) 상태 저장, 무료 TP 회복 아이템/자연 회복 판단, 현재 턴 행동/스킬/이벤트 검수 규칙, 이벤트 선택지 결과 충돌 기록 및 턴별 구조화 관측 로그를 추가했습니다. 기존 사용 데이터는 삭제하지 않습니다. **완전 자동 클릭, 한국 실게임 OCR 연동, 인기 카드 이벤트 카탈로그 완성, 검증된 ML 고점 모델은 아직 구현되지 않았습니다.** 자동 입력 호출은 검증 전 차단됩니다.

소스만 검증하는 수동 GitHub Actions 워크플로 **Validate source only (no EXE / no deployment)**를 별도 추가했습니다. 수동 실행 전용이며 이번 변경에서 새 Windows EXE·설치파일·Release는 만들지 않았습니다. R39 실행파일 버전 파일 0.31.4는 변경하지 않았습니다. 자세한 내용: [R40 변경 범위](docs/R40_통합대회_자동육성_소스개발.md).

### R41 게임 미실행 오프라인 검증 준비 (새 EXE 없음)

R40 자동 반복 코드의 TP 보유량 미확인 처리 및 상태 일관성 검사를 강화했습니다. 일본 R13 기존 조사 자료(대회 4개 × 각질 4개 = 공략 16개, 서포트 후보 34개)를 새 회차 매핑과 연결하되, **실게임 스킬 자동 구매용 정답으로 전환하지 않습니다.**

`python offline_replay_r41.py research/r41_synthetic_replay.json`으로 게임 없이 4개 가상 턴(레이스/스킬 Pt, 목표 스탯 포화, 다음 턴 필수 레이스, 체력·실패율) 및 고점/도축/실패 3회 모의 결과를 재생할 수 있습니다. 보고서는 항상 **synthetic_only=true, real_game_action=null, trained_model=false**입니다. 별도 실행파일은 없습니다.

신규 `capture_retention_r41.py`는 앱이 관리하는 별도 임시 폴더에서 **텍스트 기록을 남기고 검수 완료된 불필요한 임시 이미지**만 정리 대상으로 표시할 수 있습니다. 기본값은 **dry-run**이고 원본·미검수·예외 캡처는 삭제하지 않습니다. 현재 자동 캡처/실시간 추천과는 아직 미연결입니다.

수동 **Validate source only (no EXE / no deployment)** 워크플로에서 전체 unittest 및 가상 재생을 검사할 수 있으며, 사용자가 수동 실행해야 합니다. 이번 작업에서는 빌드, CI 실행, 자동 게임 조작은 수행하지 않았습니다. [R41 변경·검증 범위](docs/R41_게임미실행_자동육성_기반검증.md).

### R42 게임 없이 진행한 스킬 Pt·행동 안정성 검증 (빌드 없음)

재도전 중 2연패한 목표 레이스에서만, 스킬의 현재 거리·각질·마장 발동 조건과 확인된 구매 비용을 동시에 점검해 **스킬 Pt를 초과하지 않는 최대 2개 후보**를 제안하는 `skill_budget_r42.py`를 추가했습니다. 검수되지 않은 스킬/가격/게임 장면은 추천하지 않고 **실제 자동 구매는 미연결**입니다.

`intent_gate_r42.py`는 같은 턴·화면을 연속 두 번 확인하고 다음 턴/장면으로 넘어간 것을 검수하기 전에는 같은 행동을 중복 제안하지 않도록 하는 읽기 전용 상태 관리자입니다. 기존 R40 턴 상태 검증도 엄격하게 수정했습니다.

R42 핵심 로직은 로컬 합성 테스트 11개를 실행해 통과했습니다. 그러나 저장소 전체 테스트와 GitHub CI/Windows EXE/한국 게임 실검증은 이 작업에서 실행하지 않았습니다. 기존 데이터와 원본 기능은 보존합니다. [R42 변경 내용 및 검증 범위](docs/R42_오프라인_안전행동_스킬예산.md).

### R43 게임 미실행 턴 기록 연결 (소스 개발 · 새 EXE 없음)

R41 합성 턴별 판단을 R40 JSONL 턴 기록으로 연결한 `replay_pipeline_r43.py`를 추가했습니다. 4개 가상 턴 중 다음 가상 화면이 있는 3턴만 기록하고, 실제 확인이 없는 마지막 턴은 보류합니다. 기록의 `chosen_action=None`, `outcome_verified=False`, `origin=synthetic_test`와 `training_ready=False`를 유지하므로 **가상 추천을 실제 행동/학습으로 오인하지 않습니다.**

같은 가상 육성 ID·턴을 다시 돌리면 기존 기록과 완전히 동일한 경우 중복 저장하지 않고, 다르면 덮어쓰지 않습니다. 전체 턴 충돌을 먼저 확인해 뒤쪽 기록 충돌로 앞쪽 일부 턴을 추가하는 것도 방지합니다. 기본 실행은 임시 폴더에만 기록하며 `--journal`을 명시한 경우에만 영구 JSONL을 append 합니다.

`python replay_pipeline_r43.py research/r41_synthetic_replay.json`로 게임 없이 재생할 수 있습니다. R43 단독 로컬 테스트 9개 통과, 저장소 R41 실제 연결 검사는 CI 실행 전입니다. Windows EXE·자동 클릭·GitHub Release·배포는 만들지 않았습니다. [R43 개발 기록](docs/R43_가상턴_판단기록_통합검증.md).
