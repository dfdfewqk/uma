# 시나리오를 추가할 때의 구조

- `uma_core.py`: 거리·각질·목표 스탯·체력·훈련 선택지에 대한 **공통** 평가
- `scenario_policies/island.py`: **무인도만** 사용하는 발전 Pt, 티켓, 복수 우정 훈련 가중치
- `scenario_policies/island_post_patch_v1.json`: 무인도 2025-06-30 조정 후 기준 실험용 상수 (공식 수치 아님)
- `scenario_policies/__init__.py`: 화면의 시나리오 목록 및 플러그인 등록
- `storage.py`: 모든 시나리오가 공통으로 쓰는 턴별 상태·행동·실제 선택·완주·중단 정보 저장
- `dataset.py`: 저장된 턴을 **검토용 자료**로 내보내기 (ML 학습 아님)

새 시나리오는 기존 무인도 파일을 뜯어고치지 않고 별도 policy 클래스로 구현한 후 등록해야 합니다. 데이터 상태(`experimental_unvalidated` 등), 적용 서버·패치, 한국 서버 수치 검증 여부를 반드시 명시합니다. 신규 시나리오가 추가되어도 V0.1/V0.2 기존 무인도 기록의 의미가 바뀌지 않아야 합니다.

# 실패·도축 자료가 왜 필요한가

성공한 고점 육성만 기록하면 운 좋은 배치가 정답처럼 보일 수 있습니다. 사람의 선택은 **최적 행동의 정답 라벨이 아니며**, 도축했다고 해서 반드시 그 시점에 포기하는 것이 합리적인 것도 아닙니다. 실제 결과와 상황을 연결하고, 시나리오·패치·경기 조건·카드 편성을 분리하여 검증해야 합니다.

기존 `research/annotation_schema.json`은 주석용 템플릿입니다. 현재 영상 턴별 추출 실적은 0건이며, 모델 학습 결과도 없습니다. 다른 저작물의 영상 전체를 무단으로 복제하거나 재배포하지 말아야 합니다.

## R15 공통 ML 데이터층 적용 (추가)

- `scenario_features_r15.py`: 시나리오마다 별도의 **선택 전 상태 특성 어댑터**를 등록해야 합니다. 지원하지 않는 시나리오는 실수로 학습에 섞이지 않도록 내보내기를 차단합니다.
- `learning_data_r15.py`: 모든 시나리오가 공통으로 쓰는 검수·출처 그룹·패치 관리와 train/validation/test 내보내기.
- `learning_ui_r15.py`: 게임 화면을 직접 확인하는 로컬 검수 UI.
- 새 시나리오는 **공통 속성**(현재 스탯·체력·의욕·목표·거리·각질)과 **전용 속성**(고유 자원·훈련 보너스·시설)을 분리하고, 한국/일본 서버와 패치 버전을 명시해야 합니다.
- 세부 규격과 실전 검수 게이트는 `docs/R15_학습데이터_확장설계.md`를 반드시 따르세요.
