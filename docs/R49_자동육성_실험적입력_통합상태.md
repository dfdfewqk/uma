# R49 — 실게임 자동 훈련 입력 실험 / 무료 TP · 스킬 · 반복 육성 / 실결과 학습 통합 기반

## 0. 사용자 목표

무인도 한국 서버에서 `육성 턴별 효율 추천 → 클릭 → 무료 TP 부족 시 1개 회복 → 검증된 스킬 구매 → 종료 후 다음 육성 반복 → 실제 결과로 학습`을 원한다. 초반 서포트 인연을 우선하고, 한 턴의 총 이득과 부족한 스탯·스킬 Pt·미래 턴 효율을 종합해야 한다. 단, 게임 입력 화면을 확인하지 못한 조작을 추측하여 누르거나, 스탯 합계만으로 실제 랭커 수준이라고 주장하지 않는다.

본 단계에서 **실제로 연결된 기능**과 **실게임 검증 자료가 없어 입력이 막혀 있는 기능**을 명확히 구분한다.

## 1. 실제 입력 경로 — 훈련 화면에서만 실험적으로 활성

`companion.py`에서 **자동 훈련 탐색 시작 (OCR 잠정 후보 사용)** 버튼 클릭, 사용자에게 위험·제약 설명 후 명시적인 동의, 다시 게임 창을 활성화해야 한다.

`training_tour_r49.TrainingTour`은 R48 한국 서버 세로형 UI(2026-10-16 사용자 영상의 화면 비율, 노란 결정 표식)의 5개 훈련을 순서대로 클릭하여 스탯 상승 미리보기를 한 턴에서 수집한다. 원본 `PreviewCollector`의 **훈련 1개당 동일한 OCR 2회 인식**, 게임 창 ID/크기/기본 스탯 지문을 재사용한다. 5종 수치가 모두 수집되고 현재 잠정 추천이 있으면 해당 훈련을 선택하고 선택된 훈련 아래 '결정' 영역을 **사용자가 실험적 자동 동작에 동의한 경우에만** 클릭한다. 실제 인연·스킬 Pt·체력/실패율까지 반영한 검증된 1순위가 아니라 **스탯 합계 임시 후보**다.

`foreground_click_r49.ForegroundWindowsPointer`는 실행 직전 실제 게임 창 HWND/클라이언트 좌표 재조회, 활성 창 ID 확인, 창 크기 일치, 신선한 화면의 스탯 기준 지문과 선택된 노란 표식 확인, 명시적 opt-in, 단일 클릭·재사용 차단을 시행한다. Windows 일반 전경 마우스 클릭만 사용하고, 메모리 수정/백그라운드 클릭/보호 우회/네트워크 전송은 없다. 사용자는 **자동 조작 즉시 중단**을 누를 수 있다. 화면이 불확실하거나, 선택 표시가 사라지거나, 모르는 이벤트/팝업/레이스 장면이면 무리하게 진행하지 않고 정지한다.

**중요:** 실제 게임 장면에서 UI 좌표/캡처 시간·초점·훈련 '결정' 버튼 동작을 테스트한 성공 증거는 아직 없다. 자동 미리보기 순서와 클릭 위치는 해당 세로형 사용자 영상에 기초한 **실험용 규칙**이며, 실제 게임에서 완성 검증을 거치기 전 신뢰성 보장은 없다. 랭커 수준 효율 판단, 인연 위주 최적화, 이벤트/시설/레이스, 전체 20회 무중단 자동 육성은 현재 불가능하다.

## 2. 반복·무료 TP·스킬·결과 상태 판단 (단계별 계획, 아직 실제 화면 입력 어댑터 없음)

`batch_planner_r49.BatchPlanner`의 단일 루프 단계는 `setup / tp / training / skill / result / repeat`. 현재 한국 서버에서 두 차례 연속 확인한 장면만 후보를 산출한다. 앞 단계의 클릭 뒤 **새 장면 및 새 증거 ID**를 확인하기 전에는 같은 아이템·스킬·시작 버튼을 중복 누를 수 없다.

- TP: R44 `plan_tp_step`을 재사용하며 **무료로 검증된 아이템 한 개만** 후보. 유료 주얼/TP 충전은 사용하지 않는다. 실제 TP/필요량·회복 상한/아이템 잔여 개수를 관측하지 못하면 사용 금지. 부족하면 자연 회복 대기.
- 스킬 Pt: 실제 한국 서버에서 표시된 스킬 이름·발동 조건·가격·보유 여부·각질·거리·마장·Pt를 모두 검수한 경우 후보 산출. 실제 클릭 뒤 Pt/보유 상태 재확인 전 추가 구매 금지. 이 엔진의 `VerifiedOffer`는 호출자가 보상/가격을 검수했다고 선언하는 계약이고, **R48 OCR 자동 실게임 인식 단계가 아직 구현돼 있지 않다**.
- 완료/재시작: 완료 화면에서 동일 육성 ID와 결과(good/ordinary/disposed/failed)를 2회 검수한 뒤에만 완료 1회 집계한다. 이미 완료된 ID, 요청 횟수 초과, 게임 화면과 설정된 캐릭터/덱/계승 불일치는 중복 집계·재시작 금지. 현재 게임 종료/새 육성/TP 상점 이미지 템플릿이 부족해 **실제 재시작 자동 입력은 연결되지 않았다**.
- 장면 인식과 클릭 분리: `BatchPlanner`는 후보를 산출하지만, 실제 게임 스크린샷을 `StageObservation`으로 바꾸는 검수된 어댑터가 있기 전에는 **클릭 실행기와 연결하지 않는다**. 진단/일시정지만 지원한다.

## 3. 검수된 실제 결과 학습

`outcome_learning_r49`:

- **실제 한국 게임의 턴 전/후 각각 다른 증거 해시, 원본 시나리오·패치·run_id·turn_id, 사용자가 결과를 확인한 기록**만 학습 자료로 저장한다. 자동 OCR 잠정 숫자, 일본 자료, 가상 리플레이, 본인이 선택하지 않은 행동의 가상 보상은 학습 금지.
- `run_id` 기반 80/20 재현가능 train/holdout 분할, 패치/시나리오 격리. 독립 실제 검수 30개 육성·200턴 이전에는 학습 점수 없음.
- 선택한 행동의 실제 스탯·스킬 Pt·체력 변화에서만 탐색용 경험적 평균 보상을 구한다. `save_model_version`으로 덮어쓰기 없는 불변 모델 스냅샷, `load_model_version`으로 수동 복원 가능.
- `Companion`에는 패치별 실제 검수 기록 수만 읽는 상태 표시를 추가했다. **게임 내 클릭 결과를 현재 자동으로 '검수 완료'로 승격하거나 무인 학습을 시작하는 기능은 없다.** 확보해야 할 실제 자료가 없어서 학습 모델도 아직 준비되지 않았다. 충분한 자료 확보 뒤에 R46 정책을 검증하면서 연결해야 한다.

## 4. 사용자 테스트 방법과 배포

Windows 포터블의 `UmaTrainerKR_Companion.exe`에서 게임 창을 옆에 둔다. 기본 `항상 위`는 꺼져 있다. 대회 회차와 각질을 고른 후 게임에서 **훈련**을 열고, 헬퍼 상단의 실험적 자동 훈련 버튼을 누른다. 화면 설명을 읽고 동의한 뒤 **다시 게임 창을 클릭해 활성화**한다.

우선은 **실험용 자료가 있는 계정/훈련 턴에서 짧게 테스트**하고 첫 자동 클릭 직후 실제 보상과 선택 동작을 비교한다. 중단할 때는 `자동 조작 즉시 중단` 또는 창 종료. 클릭·화면 검증 실패·다른 장면·무료 TP/스킬/종료 진입에는 임의 클릭 없이 멈춰야 한다.

기존 `%LOCALAPPDATA%\\UmaTrainerKR` 기록은 R49 모듈 변경만으로 삭제·이관하지 않는다. 작업/배포 시 기존 소스는 유지하고 GH Windows Actions 전체 소스 테스트, Xvfb UI, EXE smoke, SHA256 ZIP을 모두 확인한다. **GitHub Actions 성공은 실제 게임 자동 육성 성공의 증거가 아니다.**

## 5. 완전 자동을 검증하려면 반드시 남은 부분

실제 한국 서버의 **훈련 상세/인연 표시**, **TP 부족/무료 아이템 목록 및 사용 확인**, **스킬 목록/구매 확인**, **시설/섬 이벤트/필수 레이스 및 일반 이벤트**, **육성 종료 결과·동일 캐릭터 새 육성 설정** 화면에 대한 인식/관측/전환 샘플이 필요하다. 화면마다 UI 템플릿 등록과 실제 클릭 뒤 장면 전환 실험이 있어야만 자동 반복을 안전하게 열 수 있다.

현재 구현은 완전 자동 20회 성능 개선 AI가 아니라 **R48 OCR 후보를 사용하는 단일 훈련 장면의 실험적 자동 입력 + 전체 반복·무료 TP·스킬·실결과 학습을 위한 검수 우선 기반**임을 명확히 표시한다.
