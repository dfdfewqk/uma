# Uma Trainer KR R15 — 검수 기반 학습 데이터 기반 (2026-10-15)

## 이 버전에서 **실제로** 완성한 것

- 기존 R14의 세션·턴·선택 기록(`runs.sqlite3`)은 수정/삭제하지 않고 그대로 읽는다.
- 별도의 `r15_learning_reviews.sqlite3`에 검수 증거(게임 선택 전/후 이미지 경로와 SHA-256), 검수자 메모, 서버, 패치 버전, 출처를 기록한다.
- 실제 관측한 선택지 2개 이상, 선택한 행동이 그 안에 있음, 화면 2장과 패치/출처 확인이 필요하다.
- 원본 턴 정보가 변하거나 원본 이미지가 수정되면 해당 데이터는 자동으로 내보내기에서 제외된다.
- 같은 육성이나 같은 영상에 연결된 기록을 하나의 그룹으로 합쳐 train/validation/test에 **한쪽만** 배치한다.
- 시나리오, 서버, 패치 버전, 챔미/리오히 대회별로 데이터의 학습 준비 가능성을 따로 평가한다.
- 검수된 기록만 JSONL로 내보내고, 이유가 포함된 감사 보고서를 만든다.
- 현재 실제 영상/게임으로 검수한 턴이 0건이므로 **학습 데이터셋은 비어 있으며 ML 모델을 학습·배포하지 않았다.**

## 첫 실행과 검수 방법

1. 개발 환경에서 `python -m pip install -r requirements.txt` 후 `python app.py`로 실행한다. 현재 완성된 Windows 설치 EXE는 없다.
2. ① 목표, ② 턴에서 현재 턴의 게임 상태·확인한 선택지·실제로 누른 행동을 저장한다.
3. ⑯ R15 학습자료에서 육성과 턴을 선택한다.
4. 같은 턴의 실제 게임 **선택 전 화면**과 **선택 후 화면**을 지정한다.
5. 출처(자체 게임 화면 또는 검수한 영상), 서버(KR/JP), 패치 버전, 출처 그룹 ID(같은 영상은 같은 ID), 검수 메모를 입력한다.
6. **검수 등록** 후 **전체 자료 감사**를 눌러 기초 신뢰 조건을 확인한다.
7. **학습 후보 JSONL 내보내기**를 선택한다. 출력 폴더에 train/validation/test JSONL과 감사 JSON이 생성된다.

> SHA-256은 **파일의 변경 여부**만 검증한다. 이미지가 실제 플레이를 촬영했는지 또는 입력 행동이 최적 선택인지는 자동 인증하지 못한다. 검수자가 화면을 직접 확인해야 한다. 테스트 이미지/가상 플레이를 실전으로 등록하지 말아야 한다.

## 공통 레코드 형식

`schema: uma-learning-turn-v1`, `scenario_id`, `server`, `patch_version`, `origin`, `provenance_group_hash`, `example_id`, `features`, `scenario_features`, `observed_options`, `label`, `evidence`, `split`.

`features`에는 **행동 선택 이전에 알 수 있는 값만** 담는다(경기 조건, 목표 스탯, 현재 체력, 의욕, 현재 스탯, 남은 턴). `scenario_features`에는 시나리오 전용 상태만 담는다. 일본 무인도에서는 시설 단계·섬 트레이닝 티켓·발전 Pt를 저장한다. 원본 스크린샷/로컬 절대 경로, 사용자 메모, 캐릭터 실명 메모, 추천 휴리스틱 점수, 후속 턴 결과, 최종 성공/중단 여부는 **학습 입력으로 내보내지 않는다.**

`label.chosen_action`은 사람이 한 **행동 기록**이다. `human_behavior_not_optimality`를 명시하며, 보상/승률/최적 선택의 정답이 아니다. 성공 영상만을 따라하는 ML을 막기 위해 학습 목표(상태 예측, 행동 모방, 실제 성과 예측)를 서로 구분해야 한다.

## 데이터 누출 및 버전 격리

- 한 육성 안의 여러 턴은 무조건 같은 분할로 묶는다.
- 하나의 출처 영상에서 여러 육성이 나와도 하나의 분할로 묶는다.
- 여러 영상에 걸쳐 같은 육성이 등장하면 연결 관계를 추적해 하나의 분할로 묶는다.
- 다른 서버/패치/시나리오가 동일 출처 그룹에 섞이면 해당 기록을 전부 격리한다.
- 전반적인 모델 학습 준비 여부는 **동일 시나리오 + 서버 + 패치 + 대회 형태**별로 별도 평가한다.
- 초기 보수적 게이트는 동일 그룹에서 최소 200턴, 독립 출처 30개 이상, 세 분할에 모두 자료가 있어야 통과한다. **이는 학습 정확도의 보증이 아닌 데이터 최소 검토 문턱**이다.
- 출처가 서로 다른 것처럼 보이지만 사실 같은 영상인 경우를 완전 자동으로 식별하지 못할 수 있다. 연구 검수 시 원본 영상 ID를 통일해야 한다.

## 다른 시나리오를 추가하는 방법 (필수)

1. `scenario_policies/<id>.py` 및 전용 설정 JSON에 시나리오 규칙을 추가한다.
2. `scenario_policies/__init__.py`의 `POLICIES`와 `SCENARIOS`에 새 ID를 등록한다.
3. `scenario_features_r15.py`에 `new_scenario_features(state, profile)` 함수를 만들고 `ADAPTERS[scenario_id]`에 등록한다. 신규 어댑터 없이는 검수 등록 자체가 차단된다.
4. 새 시나리오에서만 나오는 자원/시설/훈련 조건은 `scenario_features` 아래에만 넣는다. 공통 `features` 스키마를 무인도 전용으로 변경하지 않는다.
5. 서버/패치 ID를 새 버전으로 발급하고, 이전 패치가 바뀌지 않도록 보존한다.
6. 최소한 `tests/test_learning_data_r15.py`의 데이터 무결성·그룹 누출 테스트를 통과하고, 신규 시나리오 테스트를 추가한다.
7. 새 시나리오 데이터를 기존 무인도 자료와 무분별하게 합쳐 ML을 학습하지 말고, 시나리오별 평가와 전이 성능을 별도로 확인한다.

## R16/R17을 시작하기 전 충족 조건

- 사람의 실제 육성 행동과 게임 결과가 구분돼 기록돼 있어야 한다.
- 스탯 상승 모델은 턴 직후 실제 관측치가 필요하고, 승률/LoH 점수 모델은 각 경기의 실제 결과와 실전 조건이 필요하다.
- 도축한 육성은 최종 성과를 관측하지 못한 **중도 절단(censoring) 데이터**다. 곧바로 '실패' 정답으로 사용하지 않는다.
- ML 모델은 홀드아웃 출처 그룹으로 평가하며 기존 규칙 기반 엔진보다 성능이 떨어지면 교체하지 않는다.
- 모델 파일에는 학습 시나리오, 서버, 패치 버전, 데이터셋 버전, 지표, 생성일, 원복 가능한 모델 ID를 저장해야 한다.
- 개인정보 및 타인 영상의 저작권·이용 허락, 게임 서비스 약관을 확인한다. 현재 기능은 로컬 검수·저장만 하며 외부 전송/자동 조작을 하지 않는다.

## 한계

R15는 데이터 검수·내보내기 **파이프라인**이다. 자동 OCR로 원본 영상을 직접 읽거나, 행동의 최적성 정답을 판정하거나, 학습·재학습을 수행하지 않는다. 실제 한국 서버에서의 Windows 설치와 게임 화면 인식은 별도 실PC 검증이 필요하다.
