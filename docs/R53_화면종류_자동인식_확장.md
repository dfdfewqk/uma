# R53 — 한국 서버 장면 인식 확장·안전 융합
기준: R52 main `aecc0e7a0b56b5d9db7f7e91e5fbfa86e5990a95`. 원본 백업: `backup/r51-baseline-2026-10-17`.

## 구현
- 기존 R20 4종에서 12종(훈련·스킬·시설·이벤트·육성 준비·TP 회복·휴식/외출·레이스·섬 훈련·육성 결과·다음 육성·팝업/기타)으로 수동 템플릿 인식 범위 확대.
- 서로 겹친 R20 기준 두 개를 독립적인 인식 근거로 사용하지 않음.
- 신규 R53 등록창에서 실제 게임 창을 4초 뒤 로컬 캡처한 후 **서로 떨어진 고유 영역 두 곳**을 선택해 R20 파일에 추가한다. 기존 같은 장면 등록은 덮어쓰지 않음.
- R20(두 기준 영역) + R50(기등록 버튼·장면 템플릿) + R48(훈련 미리보기 잠정 신호)를 단일 장면 판정기로 융합.
- 동일 장면 두 번 연속 확인 이후 표기, 미등록·충돌 즉시 이전 장면 폐기. 장면 인식만으로는 클릭 승인이 되지 않음.
- R50 자동 실행 중 장면 충돌을 확인하면 즉시 중단. 기존 무료 TP·스킬·결과 사후 검증은 그대로 유지.

## 중요한 한계
- 인식 기준 2개 등록은 **화면의 종류에 대한 신호**일 뿐, 턴·스탯·실패율·TP·육성 ID·구매 조건의 실제 확인이 아니다.
- 사용자가 게임 자료를 제공하지 않았으므로 실제 한국 서버 화면별 인식률/다양한 팝업·로딩 구별은 검증하지 않았다.
- R48의 미리보기 잠정 인식은 별도 한국 서버 검증 없는 실험이다. 소스 테스트와 실게임 테스트를 혼동하지 않는다.
- 일본 서버/가짜/미검수 화면 데이터를 한국 서버 정확도 증거 또는 ML 정답으로 사용하지 않음.
- 기존 Windows EXE v0.32.2는 이번 변경이 포함되지 않는다. Windows 포터블 빌드/릴리스는 실행하지 않았다.

## 사용자 실제 게임 등록 방법
1. 신규 실행파일이 빌드된 뒤 Companion의 '설정·개발자 점검 보기' → 'R53 화면 종류 기준 등록' 진입.
2. 훈련·TP·레이스·이벤트·시설·스킬·육성 결과 등의 **실제 게임 화면**을 표시.
3. 화면 종류 선택 → '4초 뒤 캡처' → 게임 창 활성화.
4. A/B 각각 선택한 후 서로 다른 위치의 고유 문자/아이콘/패널을 드래그해 선택하고 저장.
5. 다른 장면을 등록하고 게임에 다시 진입해 두 프레임 후 장면 이름/보류 사유가 표시되는지 확인.
6. 게임 입력/구매/반복 검증은 이 단계에 포함하지 않는다.

## 소스 검증
- 기존 R20 합성 회귀 + 5가지 새 장면 명칭 + 겹친 앵커 거부 추가.
- 신규 R53 융합 테스트: 연속 두 프레임, unknown, conflict, provisional training, 클릭 권한 미부여 및 GUI 연결.
- 전체 GitHub Actions Windows 검사와 실제 게임 캡처 비교는 별도로 필요하다.
