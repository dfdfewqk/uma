# Uma Trainer KR — R16 로컬 ML 연구 모델 개발·검증 (2026-10-15)

## 한 줄 결론

R16은 **실제 검수된 R15 JSONL 자료로 '사람이 선택한 행동'을 학습하는 로컬 행동 모방 분류기**를 구현한다. 현재 실전 검수 턴은 **0건**이므로 실제 학습된 배포용 모델은 **없다**. 합성 테스트 데이터로는 학습/저장/평가 코드가 작동함을 검증했으며, 가상 성능은 실전 성능으로 보고하지 않는다.

## 실행 방법

1. R15 탭에서 선택 전/후 화면·서버·패치·출처 ID가 확인된 턴을 검수한다.
2. R15의 **학습 후보 JSONL 내보내기**로 폴더를 만든다. `uma_r15_train.jsonl`, `uma_r15_validation.jsonl`, `uma_r15_test.jsonl`, `uma_r15_audit.json`이 필요하다.
3. **R16 ML 연구** 탭 → `R15 자료 폴더` → 검수 코호트 선택 → `R16 로컬 학습 및 홀드아웃 평가`를 클릭한다.
4. 학습 조건이 충족된 경우에만 학습한다. 출처·패치·대회·시나리오를 섞지 않는다. 결과는 **사람의 선택과 얼마나 일치했는지**를 보여준다.
5. 연구용 모델 JSON을 직접 저장할 수 있지만 **기존 훈련 추천 / 자동 육성 기능에 자동 적용되지 않는다**.

CLI: `python ml_cli_r16.py inspect "<R15 내보낸 폴더>"` → `python ml_cli_r16.py train "<폴더>" --cohort 0 --output "<연구모델.json>"`.

## 학습 가능한 값과 불가능한 값

| 구분 | R16 가능 여부 | 이유 |
|---|---|---|
| 사람이 관측한 선택지 중에서 고른 행동의 패턴 분류 | 연구용 학습/홀드아웃 평가 구현 | R15은 실제 선택을 행동 라벨로 기록 |
| 최적 훈련 예측 | **아직 불가능** | 관측 행동의 최적성 정답, 반사실적 선택 결과 부재 |
| 최종 챔미 승률·리오히 점수 예측 | **아직 불가능** | 경기 결과, 스킬 발동/코스 등 정확한 라벨 부족 |
| 고점 완주/도축 확률 예측 | **아직 불가능** | 중도 포기 시 최종 결과가 관측되지 않음 (검열 데이터) |
| 다른 시나리오로 모델 그대로 이전 | **자동 이전 금지** | 시나리오 규칙·특징 및 패치가 다름 |

## 모델 사양

- `conditional_linear_softmax_SGD` (Python 표준 라이브러리만 사용). 관측 가능한 행동 각각에 대해 pre-action feature + 선택지 관측 상승량을 계산하는 경량 분류기.
- 입력: R15 `features`, `scenario_features`, `observed_options`에 포함된 **행동 선택 이전에 알 수 있는 값**만 사용. 실행 후 상태·최종 성공/실패·기존 추천 점수는 사용하지 않음.
- 고정된 전역 특징은 체력·남은 턴·스탯 격차·각질·거리·의욕·훈련별 예상 스탯·실패율·인연도 등. 시나리오별 특징은 `scenario_ml_features_r16.py`로 따로 계산한다.
- 학습은 train 데이터만 이용. **validation** log-loss로 epoch를 정하고, **test**는 모델/epoch 선정에 사용하지 않은 최종 홀드아웃으로 평가한다.
- 지표: 실제 사람 행동과의 일치율, macro F1, log-loss, 같은 자료의 학습 파티션 최빈 행동 비교. **어떤 지표도 실전 승률을 뜻하지 않는다**.
- 최소 게이트: 동일 `scenario_id / server / patch_version / event`에 최소 200턴, 독립 출처 30그룹, 세 분할이 존재하며 validation/test는 각각 최소 2개 독립 출처. 보수적 연구 문턱일 뿐 정확도 보증 아님.
- 모델 파일: 실행 가능한 pickle 대신 해시 검증되는 순수 JSON, `model_sha256`, `dataset_id_sha256`, 시나리오/서버/패치/대회, 훈련 epoch, 분할별 지표, `research_only_NEVER_auto_apply` 상태를 포함.
- 자동 클릭/외부 전송/온라인 학습/모델 자동 덮어쓰기/즉시 서비스 적용 없음.

## 데이터 무결성·누출 차단

- R15 내보내기 감사 보고서와 레코드 수 비교. 미검수/라벨 의미 변경, 미관측 행동, 부정확한 수치·NaN·Infinity, 파일 과대, 중복 ID/증거를 거부.
- 같은 원본 출처의 모든 턴은 하나의 train/validation/test 분할에만 있을 수 있음. 다른 출처로 둔갑한 동일 캡처도 검출.
- 하나의 출처 그룹 안에 서로 다른 서버/패치/시나리오/대회를 혼합하면 거부.
- 최종 성능에 따른 모델 자동 배포 없음. R16 JSON은 연구용으로만 유지.
- 주의: 이미지 SHA-256은 **변조 여부**만 검사한다. 그 화면이 실제 영상인지 또는 검수자가 실수했는지까지 자동 증명하지 못한다. 다른 사람이 제공한 데이터의 정확성은 별도의 출처 감사가 필요.

## 새로운 시나리오 추가 방법

1. 기존 `scenario_policies/`, `scenario_features_r15.py`에 해당 시나리오 규칙 및 R15 pre-action feature 어댑터를 추가한다.
2. `scenario_ml_features_r16.py`에 시나리오 전용 수치 4개를 **문서화한 함수**로 추가한다. 공통 특징의 의미는 변경하지 않는다. 버전이 바뀌면 ML 특징 스키마 버전도 올린다.
3. 자료의 `scenario_id`, `server`, `patch_version`, `event`를 보존하고 변경된 패치에 새 ID를 준다.
4. `tests/test_learning_data_r15.py`, `tests/test_ml_engine_r16.py`에 확장/누출 테스트를 추가한다.
5. 새 시나리오는 별도 코호트로 검수·학습·평가하며, 기존 무인도 모델을 그대로 추천에 사용하지 않는다.
6. 후속 R17에서 모델 레지스트리·버전 비교·승격/롤백을 추가하기 전까지 현재 추천 엔진을 ML로 교체하지 않는다.

## 실제 수행한 검사와 남은 한계

- 기본 R15 292개 테스트 + R16 20개 테스트 = **312개** 자동 테스트 통과.
- 18개 앱 탭 실행, R16 데이터셋 0건의 학습 차단 화면 확인.
- R16 모델 학습/홀드아웃 평가, JSON 무결성 및 데이터 누출 검사는 **합성 fixture**를 이용해 테스트함. Fixture는 연구 데이터팩에 추가하거나 실전 모델로 보존하지 않음.
- 한국 Windows 실제 EXE 빌드/설치, 한국 게임 화면 OCR, 실제 일본 육성 영상 검수, 실전 모델 정확도는 여전히 **미검증**.
- 게임 이용 약관, 커뮤니티/동영상 저작권과 자료 이용 조건을 따로 확인해야 함.
