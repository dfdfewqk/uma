# Uma Trainer KR R5 — 기능·검증 보고서

작성: 2026-10-15 · 단계: V0.5.0 연구용 시제품

## 구현
- 기존 V0.4 R4 전체 기능과 SQLite 저장·일본 연구자료 보존
- 훈련 5종 및 섬 트레이닝(티켓 있을 때)의 개별 스크린샷 검수
- 숫자 영역 직접 지정 후 로컬 Tesseract 후보 확인, 수동 수정/확정
- 필수 스탯 상승량 5개, 스킬 Pt, 실패 확률, 체력 변화를 모두 확인한 후 비교
- 섬 트레이닝은 우정 발동 시설 수 확인 추가
- 누락값 0 처리 방지, OCR 후보 자동 승인 금지, 화면 변경 시 이전 확인 데이터 폐기
- 스탯·남은 턴·육성 목표 등 현재 턴 환경이 바뀌면 이전 검수 자료의 재사용 차단
- 비교 후 '② 턴 분석' 편집창으로 검수한 선택지 전달. 휴식/레이스/외출은 초기화하여 별도 확인 요구
- R5 개별 검수 기록을 JSON으로 선택적 출력, 모델 학습의 정답 레이블로 취급하지 않음
- 창 크기가 작으면 R5 탭 내부 스크롤로 이동 가능

## 검증
- 이전 R4의 51개 테스트와 R5 신규 16개 테스트를 포함해 **총 67개 unittest 통과**.
- Linux Xvfb에서 tkinter 화면 생성, 7개 탭 표시, 추천 보류 → 전체 훈련 입력 → 순위 → ② 턴으로 전달하는 기본 동작 확인.
- OCR 엔진의 합성 이미지 인식 결과는 R4 테스트에 포함. R5 후보 추출과 오류 처리 단위 테스트는 모킹으로 확인.
- Windows EXE/Setup 실제 빌드·설치 테스트: **미실시**.
- 한국 서버 실제 우마무스메 훈련 화면 인식 테스트: **0건**.
- 일본 성공/도축 영상의 실제 턴별 검수 완료: **0건**.
- ML 학습: **미실시**.

## 주의할 제한
1. 점수는 공식 게임 수식이 아닌 임의의 실험적 비교 점수다.
2. 5개 일반 훈련 (+ 티켓 있을 때 섬 훈련) 간의 비교에 한정. 휴식·레이스·외출·이벤트·시설 건설의 최적화는 아니다.
3. OCR은 Tesseract가 설치된 환경에서만 동작하며, 반드시 사람의 확인을 거친다.
4. 체력 변화의 부호는 OCR로 추정하지 않고 직접 기록한다.
5. 각 훈련 선택 화면에서 같은 턴의 수치를 확인하고, 게임 턴을 변경했으면 다시 검수해야 한다.
6. 원본 이미지/영상은 별도 출처 및 이용 조건을 존중해 사용자가 로컬에서 확보한 자료만 직접 검수한다.
7. 실전 챔미/리오히 성능, 도축 성공확률 또는 미래 스탯 예측은 구현되지 않았다.
