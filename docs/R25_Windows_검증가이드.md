# R25 Windows 빌드·설치·실사용 검증 안내

## 검증 목적

사용자 경험은 **한국 우마무스메 실행 → 도우미 실행 → 게임 위 추천 표시 및 옆 정보 표시**다. 이번 R25는 그 동작의 전제인 Windows 설치·실행 안정성을 검사하는 데 집중한다. 실제 화면 인식 정확도나 자동 육성의 완성을 의미하지 않는다.

## 권장 수동 빌드 절차

1. 개발 소스를 전용 GitHub 저장소의 루트에 보존해 업로드한다. 기존 다른 게임 저장소를 덮어쓰지 않는다.
2. `Actions` → `Build and verify Windows installer (manual only)` → `Run workflow`를 선택한다.
3. Windows runner에서 소스 테스트를 먼저 통과해야 EXE 빌드 단계로 넘어간다.
4. 생성된 EXE 네 개를 실제 프로세스로 실행해 `--self-check-report` 결과를 저장한다.
5. 설치형 EXE를 빌드해 Windows 러너에서 설치→실행 점검→제거를 시도한다.
6. 성공 시 `UmaTrainerKR-R25-Windows-Verified` 아티팩트에서 `UmaTrainerKR_Setup_0.25.0.exe`, `SHA256_MANIFEST.json`, 각 EXE를 확인한다.

이 워크플로는 **수동 실행만 지원**하며, 성공해도 GitHub Release를 게시하지 않는다. 실제 러너에서 예기치 않은 실행 오류가 발생하면 파일 다운로드를 성공으로 표시하지 않는다.

## 필수 요소와 한계

- 운영 체제: Windows x64 빌드 기준, 실제 Windows 10/11 PC 호환성 미검증.
- Python 별도 설치: 빌드에 성공한 설치파일을 쓰는 최종 사용자에게는 불필요.
- OCR: 외부 Tesseract 설치가 없으면 수치 자동 OCR은 동작하지 않는다. 수동 검수는 가능하다.
- 보조 화면: 작은 도우미는 게임 창 옆 배치. 게임 위 추천은 화면 기준 등록과 검증이 필요.
- 자동 클릭: 구현되지 않았고 EXE 검사는 게임에 입력을 보내지 않는다.
- 사용자의 육성 기록, 이미지, 스킬 설정, 개인 파일을 빌드 과정으로 전송하지 않는다.

## 진단 JSON 해석

각 실행파일의 `--self-check-report <경로>` 모드는 GUI 없이 **의존성과 필수 데이터 파일**의 존재를 검사한다. `result`가 `PASS`인 경우에도 게임 장면 인식이나 최적 훈련 계산 결과를 보장하지 않는다. Windows CI가 아닌 Linux 환경에서 실행한 자체 검사는 `frozen_binary=false`로 표시한다.

실제 인식 정확도는 **한국 서버 스크린샷을 기반으로, 수동 확인한 정답과 프로그램 OCR 결과를 대조한 별도 리포트**로 측정해야 한다.

- [ ] 게임 창 자동 탐색
- [ ] 창 이동/크기 조절 후 게임 옆 배치
- [ ] 한국 서버 무인도 훈련 화면 탐지

- [ ] OCR 오류 발생 시 잘못된 추천 보류
- [ ] 스킬 구매 화면 OCR과 현재 각질·코스 근거 일치 확인
- [ ] 화면 전환/턴 변경 뒤 기존 추천과 좌표 무효화
