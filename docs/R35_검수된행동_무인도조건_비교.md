# Uma Trainer KR R35 — 검수된 현재 행동과 무인도 장기 조건 대조

## 목표와 현재 상태

R34의 인연·섬 티켓·시설·필수 레이스/외출 조건을 **R6에서 가능 여부와 수치를 검수한 이번 턴의 행동**에만 연결합니다. R6 실험 점수는 그대로 표시하고, R35만의 가중치나 새로운 최적 행동 순위는 만들지 않습니다. JP 2025-06-30 조정 후 공략은 연구 가설입니다.

코드: island_choices_r35.py (순수 비교) / island_context_ui_r34.py (동일 탭 버튼) / app.py (R6의 기존 검수 조회 경로 재사용).

## 사용 방법 (새 Windows 빌드 검증 이후)

1. Companion → 상세 설정·자료 관리 → UmaTrainerKR.exe → 연구·상세 설정 보기.
2. ① 목표와 ② 턴에서 목적·목표·실제 스탯·티켓·가능한 행동 수치를 입력합니다.
3. ⑦ R6에서 모든 행동의 가능/불가를 명시하고 R6 전체 행동 비교를 실행합니다. 미확인 행동은 보류됩니다.
4. R34 무인도 조건 탭에서 첫/이후 티켓, 인연, 우정 시설 수, 남은 필수 레이스, 다음 레이스까지 턴, 남은 외출, 성장률·시설 확인 여부를 입력합니다. 모르는 값은 비워 둡니다.
5. R35 확인된 행동 비교 버튼: 검수된 행동의 R6 실험 순위, 입력 스탯 상승, 사용자 목표 부족분 기여, 선택 후 체력, 스킬 Pt·발전 Pt 및 조건별 경고를 표시합니다.
6. R34 입력 변경이나 탭 이동 시 이전 비교를 무효화합니다. R6에서 목표·턴·행동이 변경됐다면 다시 검수해야 비교할 수 있습니다.

## 행동별 검토 항목

| 행동 | 확인 자료 | 보류 또는 추가 조건 |
| --- | --- | --- |
| 5개 스탯 훈련 | 입력 상승량, 사용자 목표 부족분에 기여하는 부분, 선택 후 체력 | 사용자 목표를 실제 스탯 상한으로 간주하지 않음 |
| 섬 트레이닝 | 보유 티켓, 초기/이후 사용 구분, R6 우정 시설 수 | 초기 인연 목적 조기 사용 예외, 이후 복수 우정, R34·R6 입력 불일치, 목표 레이스 충돌 |
| 휴식 | 확인한 체력 회복 | 미래 서포트 배치 및 훈련 성과 미예측 |
| 외출 | 입력한 자원 변화 | 후속 외출 보너스·남은 외출과의 관계 추가 검증 |
| 레이스 | 입력한 스킬 Pt·발전 Pt | 필수 출전인지, 힌트 등 다른 이득과 기회비용 검토 |

## 입력 및 검수 정책

- R6 검수 결과가 없다면 아무 행동도 비교하지 않습니다.
- 목표/턴 지문, 행동 입력 해시, 검수된 가능 여부와 행동 목록 전체가 일치해야 합니다.
- 섬 훈련 우정 시설 수가 R34 수동 값과 R6 입력에서 다르면 판단 보류입니다.
- R34 입력이 불완전하면 확인된 값만 보여주고 장기 우열은 보류합니다. 빈칸을 0으로 대체하지 않습니다.
- 자유 턴 상한 = 전체 남은 턴 - 필수 레이스 수. 기타 강제 일정을 제외하지 않으므로 정확한 자유 턴이 아닙니다.
- 스탯 목표 부족량 기여 = min(입력 상승량, max(0, 사용자 목표 - 현재 스탯)). 실제 획득 상한/성공 보장이 아닙니다.
- 일본 연구 R33의 시설 강화·티켓 가설을 새 수치 가중치나 ML 정답으로 승격하지 않습니다.

## 회귀 검사와 배포 경계

- 작성한 합성 회귀 검사: python -m unittest discover -s tests -p test_island_choices_r35.py -v (14건).
- 전체 소스 검증: python -m unittest discover -s tests -v 및 python -m compileall -q .
- **새 전체 테스트와 Windows EXE의 성공은 아직 확인되지 않았습니다.** R31.1 배포 ZIP은 보존하고 검증되지 않은 EXE를 배포하지 않습니다.
- decision_r6.py, uma_core.py, storage.py, VERSION.txt, package_selftest_r25.py는 변경하지 않았습니다. 저장 스키마·버전·ML 모델·자동 클릭을 변경하지 않습니다.
