# R44 소스 통합 점검 및 게임 미실행 구현

기준: GitHub \`dfdfewqk/uma\`, R43 HEAD \`55b2d25d7c80f3333c96f4cb846f438e4b979a7a\`.

이번 변경은 **전체 동작 테스트를 실행하지 않고** 관련 코드를 정적으로 점검해 게임이 없어도 구현 가능한 기능과 안전 장치를 일괄 보강한 소스 수정이다. 별도 Windows 실행파일, installer, GitHub Actions 실행, Release 배포, 실제 게임 클릭은 **없다**. 정상 동작이 실증됐다고 주장하지 않는다. R40~R43 사용자 데이터·기존 학습 데이터·이미지·원본은 삭제하거나 이관하지 않는다.

## 2. 수정·추가된 소스

- \`companion.py\`: 통합 회차·각질·반복 계획 메뉴. 평상시 UI에서 훈련 수치를 수동 입력하지 않음. 기존 R28/R37 기능 보존. 반복 횟수는 **설정 계획만 저장**, 자동 게임 실행 버튼이 아니다.
- \`planning_prefs_r44.py\`: 계획 횟수 독립 저장/복원. 기존 \`helper_target_r39.json\`이나 다른 프로젝트 기록 변경 없음.
- \`tp_strategy_r44.py\`: 여러 종류의 보유 **무료** 아이템 중 1개 사용 후보 평가(상한 낭비량 고려). 보유량·회복량·상한 미확정이면 사용 보류. 유료 아이템/게임 재화는 선택하지 않음.
- \`cultivation_session_r44.py\`: R40의 동일 캐릭터·서포트 덱·계승·대회 목표와 반복 횟수 유지. 확인된 육성 시작·종료(고점/평범/도축/실패를 모두 1회), TP 부족/회복 확인, 오류 일시 정지/재개와 새 R44 세션 파일의 원자적 저장/복원. 파일을 읽고 다시 시작해도 실게임 확인 전에는 반드시 paused 상태로 설정. 게임에 대한 직접 입력 기능 없음.
- \`readonly_observation_bridge_r44.py\`: 미래의 **검수된** 화면이 들어왔을 때만 R40 추천과 R42 화면 안정성 게이트를 합침. 추천은 제안/이유만 돌려주고 게임 입력을 보내지 않음. 훈련 외 화면은 별도의 검증된 장면 결과로 확인 가능하도록 분리.
- \`evidence_store_r40.py\`, \`replay_pipeline_r43.py\`: 기존 단일 턴 JSONL 기록을 유지하면서 R43의 여러 가상 턴만 새 보조 함수를 통해 통합 저장. 충돌은 사전 검사 후 중단, 기존 파일에 동시 쓰기 하는 경우는 별도 잠금이 필요함. **검수되지 않은 합성 사례는 training_ready=False를 유지**.
- 기존 \`auto_core_r40.py\`, \`turn_policy_r40.py\`, \`skill_budget_r42.py\`, \`intent_gate_r42.py\`, \`race_outing_r38.py\`, \`support_events_r40.py\`, \`learning_data_r15.py\`는 중복 구현을 피하기 위해 수정하지 않음.

## 3. 자동 육성 최종 요구사항과 연결 상태

자동 육성을 20회로 지정한 경우 도축할 결과나 실패도 완료 1회에 포함하여 **총 20회의 육성 완료/실패 종료**로 집계한다. 7번째 좋은 결과가 나와도 사용자 반복 횟수 설정은 유지한다. 게임에 재접속할 경우 진행 중 동일 육성을 새 육성으로 세지 않는다. 캐릭터/덱/계승/대회/각질은 사용자 최초 설정을 유지한다.

매 턴의 훈련·레이스·외출·시설·이벤트를 비교하는 **휴리스틱 연구 엔진**은 소스 단계에 있다. 단기 특기율 버프가 다음 턴 필수 레이스 때문에 무용해지는 상황을 처리할 규칙도 있다. 스킬 Pt는 원칙적으로 육성 마지막에 사용하고, 연속 2회 레이스 실패 시에는 현재 레이스 거리·각질·예산 조건에 맞는 최대 2개의 스킬만 예외적으로 구매 후보를 만든다. 화면에서 실제 보유/발동/가격을 확인하지 않은 스킬은 구매하지 않는다.

실제 완전 자동화까지 남은 것은 **진짜 KR 화면의 캐릭터·덱·계승·서포트 위치/인연·우정·이벤트 선택 결과·터커 SSR 단계·레이스 결과·TP 회복·스킬 구매·육성 완료 인식 및 검수**, 그리고 이를 기반으로 한 게임 내 입력 어댑터다. 게임을 못 켜는 상태에서 이 자료를 상상해서 채우거나 자동 조작 성공으로 표시하지 않는다.

## 4. 연구·학습 데이터 보호

- 일본 2025 이벤트 4개, JP 출처 프로필 16개, 연구 카드 후보 34개는 기존 R13/R14 데이터로 유지한다. 한국 실제 개최 조건과 JP 연구를 분리한다.
- 이미지 보관 정책 \`capture_retention_r41.py\`는 변경하지 않는다. 독립 앱 전용 임시 폴더에서 텍스트 기록으로 대체한 검수 이미지에만 삭제 후보 표시 가능하며 기본은 dry-run. **사용자가 보관한 원본/기존 캡처 자동 삭제 금지**.
- R15 학습 데이터 검수/훈련-검증 누출 방지 정책은 유지한다. R44는 학습된 모델·검증된 최적 승률 예측을 새로 만들어 내지 않았다.
- 기존 \`runs.sqlite3\` 및 \`helper_target_r39.json\` 형식을 새 파일로 강제 이관하지 않는다. 새로운 횟수/세션 저장은 별도 파일이며 실제 확인 전에는 실행 상태를 임의 복원하지 않는다.

## 5. 이번 단계에서 하지 않은 일

요청에 따라 \`python -m unittest\`, GitHub Actions, Windows CI, EXE 빌드, 실게임 실행, 레이스 시뮬레이션, 자동 클릭 테스트를 실행하지 않았다. 따라서 **R44는 소스 구현·정적 검토 단계이며, 테스트 통과가 아니다.**

실행 재개 때 첫 번째로 확인할 사항: 컴패니언 클릭형 시작 메뉴/기존 R37 UI 회귀검사 → R44 세션·TP·턴 어드바이저 순수 함수 검사 → 소스 전용 CI → Windows 실행 → 게임 화면 검수 → 실제 자동 입력·복구 순서. 테스트 실행 전 R44를 완성된 자동 육성 도구로 배포하지 않는다.
