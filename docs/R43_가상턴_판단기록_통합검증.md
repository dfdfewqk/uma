# R43 — 오프라인 턴 판단 → 다음 가상 화면 → 텍스트 기록 연결

## 목표와 범위

R41의 합성 턴별 행동 점수 계산 결과를 R40 텍스트 기록 형식에 연결한다. R42의 게임 입력 차단 정책은 그대로 보존한다. **실제 게임 실행/화면 인식/버튼 자동 클릭/학습 완료가 아니다.** 자동 Windows EXE 빌드, 배포, GitHub Actions 실행도 하지 않는다.

## 구현: replay_pipeline_r43.py

- R41의 `replay_case()`가 반환한 정해진 합성 결과만 받고, synthetic_only=true, game_opened=false, game_clicked=false, trained_model=false, real_training_samples=0를 강제한다.
- 가상 N턴 데이터에서 각 턴의 다음 가상 화면이 존재할 때만 R40 `TurnObservation`으로 전환한다. **마지막 턴은 완료/보상 검증으로 처리하지 않고 보류**한다.
- 각 턴의 비교 점수·가상 1순위 이름과 다음 가상 화면의 상태만 남긴다. `chosen_action=None`, `outcome_verified=False`, `screen_verified=False`, `origin=synthetic_test`로 저장해 실제 게임 행동·학습 데이터로 잘못 집계되지 않게 한다.
- 선택지가 일부 누락되거나 하나라도 검수되지 않은 가상 턴은 기록 대상에서 제외하고 `blocked_turns`로 보고한다. 이 검수는 가상 자료 내부 완결성 검증이지 한국 게임 검증이 아니다.
- `run_id + turn_id`별 기존 기록을 먼저 불러와 동일 내용이면 저장하지 않는다(중복 방지). 충돌하는 턴 기록이 있으면 기존 자료를 덮어쓰지 않고 중단한다.
- 재생 전체의 충돌 검사를 먼저 끝낸 후 새 줄을 JSONL에 추가한다. 단일 프로세스 기준 추가 기록의 충돌 사전 검사를 수행하지만 동시 프로세스 파일 잠금/완전한 다중 행 트랜잭션은 아직 추가하지 않았다.
- 기본 CLI는 임시 폴더에서만 실행해 영구 파일을 남기지 않는다. 사용자가 `--journal`을 지정하면 파일을 삭제·초기화하지 않고 append-only 기록한다.

## 실행 방법 (게임 없이)

```bash
python replay_pipeline_r43.py research/r41_synthetic_replay.json
python -m unittest discover -s tests -q
```

첫 명령의 기대 동작: 가상 4턴 중 다음 화면 확인된 3턴만 기록, 마지막 4턴 보류, 실게임 행동 0건, ML 학습 0건. 저장한 기록을 확인하려면 다음처럼 명시적으로 경로를 지정한다.

```bash
python replay_pipeline_r43.py research/r41_synthetic_replay.json --journal r43_offline_turns.jsonl
```

## 테스트 근거/제약

`tests/test_replay_pipeline_r43.py`는 중복 기록, 뒤쪽 충돌 발생 시 앞쪽 일부 기록 방지, 기존 데이터 불변, 입력·학습 오인 방지, 미확인 선택지 차단, 서로 다른 육성 ID의 기록 분리, 마지막 턴 보류 등을 검사한다.

- R43 모듈 및 테스트 9개는 로컬 Python 3.13에서 독립 수행하여 통과했다. 단 기존 R41 통합 어댑터는 이 로컬 작업 폴더에 전체 R41 소스가 없어서 **전체 저장소 CI 검증 전**이다.
- GitHub 저장소에서 실제 R41 모듈과 새 연결부를 함께 검사하는 1개의 통합 테스트를 추가했다. 소스 전용 워크플로에서도 R43 CLI를 추가 검사한다.
- 이 작업 중 GitHub Actions 워크플로는 **수동 실행 설정만 유지**하고 실제 실행하지 않는다. Windows 빌드·EXE·Release 생성 없음.
