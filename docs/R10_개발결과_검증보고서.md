# Uma Trainer KR R10 — 수정 후 육성 영상 검수 작업 관리

## 개발 목적과 범위

- R9 프로그램과 R1~R9 데이터를 보존한 상태에서 R2 영상 검수 → R9 실측 검증 사이의 수동 검수 절차를 연결.
- 최초 지원 범위는 한국 서버 PC 전용, 일본 서버 2025-06-30 수정 후 무인도 영상 참고, 챔피언스 미팅/리그 오브 히어로즈 본육성 연구.
- 고점 성공 사례뿐 아니라 중도 포기, 인자작, 일반 평가점 등의 표본도 **별도 목적**으로 구분. 인자작·평가점 사례는 R9 챔미/리오히 본육성 수치에 혼합하지 않음.
- 원본 영상 다운로드, 게임 클라이언트 조작, 무단 영상 일괄 수집, ML 훈련 **없음**.

## 이번 구현

1. `review_pipeline_r10.py`: R1 출처, R2 우선순위, 12개 설명 기반 영상 챕터를 병합한 **검수 작업 17건** 생성. 챕터 타임스탬프는 검수 지점일 뿐 실제 턴 데이터가 아님.
2. `review_ui_r10.py`: ⑪ R10 영상 탭에 작업 목록, 상태 표시, 영상 열기, 근거 ID 연결, 보류/검수 중 표시, CSV 내보내기.
3. 검수 작업은 `pending` / `in_review` / `blocked` / `verified`를 구분. `verified`는 R2 `verified_turns.csv`의 실제 선택 전/후 검수 기록, 일치하는 출처, 원본 이미지 SHA-256, 챕터 시점 근접성을 검증한 경우만 허용. 원본이 바뀌면 `blocked`로 표시.
4. `export_r9_verified`: 별도 JSON 배열에서 수동 검증한 **훈련 화면의 5스탯 상승량 + 스킬 Pt 표시값 6개**, 시설 레벨/분기, 우정 인원, 카드 편성, 시기, 패치 증거를 모두 검증한 경우에만 R9 CSV 형식으로 출력.
5. R9 필터를 재사용하므로 **2025-07-01 이후 JP 수정 후** 자료만 통과. 서버, 대회, 캐릭터, 카드 편성 등을 섞지 않음.
6. 출력은 입력 R2 CSV, 입력 수동 JSON, 기존 R9 CSV를 덮어쓰지 않음. 진행상황은 별도 JSON에 원자적으로 저장.
7. R10 수치 전달은 **선택된 행동의 최적성 라벨**을 만들지 않음. 오직 화면에서 표시된 관찰 수치를 전달.

## 데이터 현황 (2026-10-15)

- 영상 출처를 위한 검수 작업 17건 생성: 그중 R1의 S010 영상에 해당하는 챕터 12개는 **설명 기반 탐색 지점**으로만 관리.
- 실물 영상을 열어 사람이 검수한 선택 전후 턴은 **0건**.
- R10이 R9에 보낸 검수 관찰값 **0건** (현재 실제 입력 JSON이 없음).
- 샘플 수치나 생성 이미지로 실행한 테스트는 `tests/` 안에서 격리. 실제 연구 CSV에 섞지 않음.
- 완성된 ML 모델, 자동 육성, 한국 서버 실화면 검증, Windows EXE 실행 검증 **없음**.

## 테스트

- `python -m unittest discover -s tests -q`
- 실행 확인: Linux Xvfb에서 `app.UmaApp()`를 생성한 뒤 R10 탭 선택, 17행 표시 확인.
- 기존 162개 테스트 + R10 개발용 신규 테스트 24개, **총 186개** 통과. (정확한 수는 소스 기준 자동 수집 결과로 재확인)
- **Windows 설치형 EXE는 구성만 업데이트했고 실제 Windows에서 빌드하거나 실행하지 않음.**
- GUI `examples/R10_영상검수_실행화면.png`은 영상 검수 작업 목록을 보여주는 실제 프로그램 실행 화면이며, 검수된 원본 영상 프레임을 포함하지 않음.

## 왜 검수를 엄격하게 제한하나?

- 고점만 선별된 영상은 선택 편향이 있음. 도축이 기록되지 않은 경우 완료 시점에서 결과를 거꾸로 최적이라고 추론하면 안 됨.
- 유튜브 설명의 타임스탬프만으로 각 턴의 훈련 결과, 성장 수치, 선택 행동을 확정할 수 없음.
- 게임 시스템 패치일, 영상 게시일, 실제 녹화일이 다를 수 있으므로 날짜와 패치를 별도로 검수.
- 어떤 플레이어가 선택한 행동인지와 동일 상황에서 가장 좋은 행동인지의 구분을 유지.
