## 2. R40 자동 육성 소스 단계 구현

- auto_core_r40.py: 캐릭터/덱/계승/목표 고정, 반복 횟수 및 TP 관측값 검수, 무료 TP 아이템 후보/자연 회복 대기 판단, 고점·평범·도축·실패를 각각 **1회씩** 계산하는 실행 상태 및 중복 ID 차단, 로컬 결과 원자적 저장과 재시작 복원. 남은 레이스 재도전은 새로운 육성으로 카운트하지 않는다.
- turn_policy_r40.py: 검수된 현재 화면의 여러 행동에 대한 연구용 턴별 효율 비교. 목표 스탯을 대부분 채운 이후 스킬 Pt 가중을 높이고, 인연·우정·체력·실패율·다음 턴 특기율과 필수 레이스 충돌을 비교한다. 검수된 옵션이 부족하면 추천을 보류한다. 이 숫자 가중치는 임시 휴리스틱이지 검증된 고점 정책이나 학습된 승률 모델이 아니다.
- turn_policy_r40.py: 목표 금색 스킬 연속 이벤트/조기 종료/마지막 스킬 획득 분기 검토, 같은 레이스 2연패 시 **현재 출전 거리·각질·마장에 맞는 스킬 최대 2개**만 예외적으로 검토. 최종 챔미용 스킬 구매와 레이스 돌파용 스킬 구매는 분리해야 한다.
- support_events_r40.py: 게임 내 효과 미리보기 **및** 실제 결과가 둘 다 확인된 카드/버전/패치/연속 이벤트 선택지만 카탈로그로 승격. 서로 다른 효과가 나오면 덮어쓰지 않고 'conflict' 상태로 격리한다. 사전 인기 카드 이벤트 본문/선택지 데이터는 아직 구축되지 않았다.
- evidence_store_r40.py: 턴별 수치·결정·실제 보상 데이터를 JSONL 텍스트로 축적하는 준비 구조. 자동 증거 전송·스크린샷 삭제 없음. 초안/합성 데이터는 학습 완료 또는 검증된 학습 라벨로 표시하지 않는다.
- actuate_game(): **기본 차단**. 한국 클라이언트 버튼/이벤트/TP/완료 화면의 검수된 인식과 게임 조작 어댑터를 연결하기 전에는 자동 클릭 없음. 게임 내 실제 조작 성공을 주장하지 않는다.

## 3. 합의된 최종 자동 운용

사람이 최초 캐릭터·서포트·계승 및 대회 회차·각질·반복 횟수를 정한다. 이후 같은 설정으로 총 N회 계속 육성하고, 좋은 결과든 도축각이든 종료 카운트에 포함한다. TP가 부족하면 검증된 무료 아이템을 사용하며 부족 시 자연 회복을 기다린다. 유료 재화 자동 사용은 금지한다. 육성 실패로 불가피하게 종료되는 경우를 제외하고 가능한 육성은 끝까지 진행한다. 매 턴의 훈련·레이스·외출·시설·이벤트·스킬에 대하여 현재 확인된 효율과 다음 턴에 실제로 활용 가능한 효과를 비교한다. 최종 출전 여부는 사용자가 결정한다.

## 4. 구현되지 않은 연결부와 테스트

- 실제 KR 게임에서 자동으로 캐릭터/덱/계승·훈련 지원인원·우정·인연·레이스 보상·터커 단계·이벤트 효과 미리보기·스킬 구매 버튼·TP 회복아이템·육성 완료를 신뢰성 있게 읽는 과정은 검증 미완료.
- 실제 자동 게임 클릭, 전체 게임 장면별 행동 실행 및 결과 피드백 루프, 인기 서포트 이벤트 전체 데이터, 성능 검증된 ML/AI 모델은 미구현.
- tests/test_target_r39.py, tests/test_auto_r40.py, tests/test_support_events_r40.py는 합성/논리 회귀 테스트다. 신규 소스는 실제 Windows 테스트가 아니다.
- 별도 수동 source-only-r40.yml 워크플로는 EXE/포터블/Release 빌드 없이 Python 코드 구문과 전체 unittest만 확인하도록 분리했다. 사용자가 원할 때만 GitHub Actions에서 실행한다. **이번 작업에서는 실행하지 않는다.**
- 기존 자동 배포 워크플로 변경 없음. 기존 정상이었던 R36 바이너리 및 사용자 로컬 기록 보존.

다음 개발에서는 실게임 화면별 검수 캡처/좌표 라이브러리부터 완성하고 R40 순수 판단 모듈을 Companion의 관측 파이프라인에 연결한 뒤, 실게임 안전 입력 어댑터를 별도 단계로 완성해야 한다.
