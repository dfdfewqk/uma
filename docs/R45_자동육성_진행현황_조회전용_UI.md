# Uma Trainer KR R45 — 자동 육성 계획·진행 현황 읽기 전용 통합

## 적용 범위

기준: R44 소스(main `4b6d2d309a0f549eea1772b1a475f95582e47cb0`). 기존 Companion을 새로 만들지 않고 클릭형 시작 설정에 **저장된 자동 육성 진행 현황 영역**을 추가한다. 기존 R39/R44 설정과 사용자 기록의 데이터 스키마·내용은 변경하지 않는다.

사용자가 정한 방향에 따라 **이번 단계는 R45 한 단계만 진행**하고, 게임 없이 개발 가능한 소스 코드만 추가한다. Windows EXE, GitHub Actions, Release, 배포 또는 실제 게임 실행은 하지 않는다. 전체 테스트도 실행하지 않았으며 코드 반영은 통과 검증을 의미하지 않는다.

## 1. 화면 동작

시나리오는 무인도(2025-06-30 조정 이후)이며 대회는 챔미/리오히 **통합 1~4회차**, 각질은 도주·선행·선입·추입을 클릭으로 선택한다. 반복 횟수는 기존 R44 설정을 사용하며 기본값은 20회다. 별도의 게임 수치 수동 입력은 필요하지 않다.

시작 설정 바로 아래에 **자동 육성 현황 · 저장된 기록만** 카드가 보인다.

- **아직 세션 파일이 없으면**: “자동 육성 시작 전”, “기록된 진행 없음 · N회 계획”을 표시한다. `0/N회 완료`로 표시하면 실제 확인되지 않은 기록을 0회로 단정하므로 그렇게 하지 않는다. 진행률 막대도 숨긴다.
- **정상적인 R44 세션이 저장돼 있고 현재 목표·반복 횟수와 일치하면**: 검수된 세션의 완료/요청/남은 횟수와 고점·평범·도축·실패 집계를 표시한다. 저장된 `waiting_tp` 상태는 TP 자연 회복 대기로, `tp_refresh_required`는 무료 아이템 사용 후 TP 재확인 대기로 표시한다. 프로그램 재시작 후에는 반드시 일시 정지 안내를 표시한다.
- **진행 중이던 세션(`in_run`)**: 진행 중인 육성 ID를 중복으로 완료 횟수에 더하지 않는다. 같은 캐릭터·서포트·계승과 현재 육성 ID를 실게임에서 재확인해야만 향후 재개 가능하다.
- **현재 선택과 저장 세션이 다르면**: 이전 기록의 수치는 “이전 육성 계획의 기록”이라고 밝히고 현재 계획으로 가져오지 않으며 기존 파일을 변경하거나 덮어쓰지 않는다.
- **기존 파일이 손상되거나 모르는 형식/링크인 경우**: 진행 현황 읽기를 보류하고 원본을 그대로 유지한다.
- **‘저장된 진행 기록 다시 확인’ 버튼**: 디스크에서 조회만 새로 한다. 시작, 자동 클릭, 재개, TP 아이템 사용 또는 기존 진행 기록 초기화와 연결되어 있지 않다.

헬퍼 R37 기존 버튼 “화면 분석 일시 정지”와 R45의 자동 육성 상태 표시를 서로 혼동하지 않는다. 전자는 화면 감시를 멈추는 버튼이고 후자는 R44 자동 육성 세션의 **읽기 전용 진행 상황**이다.

## 2. 변경 파일과 새 모듈

- `session_dashboard_r45.py`: 현재 선택한 `Target`과 `Preferences`를 저장된 `CultivationSession`과 비교해 읽기 전용 `Dashboard` 객체를 만든다. R44의 `load_session()`이 재시작 후 반드시 `paused`로 반환하는 정책을 유지한다. 추가 확인 없는 자동 실행은 항상 `permits_game_input=False`다.
- `companion.py`: 해당 `Dashboard`를 StringVar 4종과 진행률 막대(검증된 세션이 있을 때만), 수동 새로고침 버튼에 연결한다. 기존 상단 클릭형 설정과 R28 훈련 힌트, 게임 탐색 기능을 그대로 유지한다. 회차/각질/반복 횟수를 바꾸면 현황 표시만 다시 산출한다.
- `tests/test_session_dashboard_r45.py`: 저장된 세션 없음, 이전 계획과 현재 계획의 불일치, 일시 중단, 진행 중 육성 중복 집계 방지, 손상 파일 원본 보존, 완료 결과, 심볼릭 링크를 검사하도록 테스트 케이스 9개를 작성했다. **이번에는 실행하지 않았다.**

R44 저장 기록의 현재 조회 위치는 `screen_r4.user_dir() / cultivation_session_r44.json`이다. 이 경로의 파일을 생성·이관하거나 사용자의 기존 데이터를 찾아 강제로 합산하지 않는다. 추후 검수된 실제 게임 연동 어댑터가 같은 경로로 저장하는 일이 필요하다. 현재는 아직 게임 화면과 R44 세션 저장 경로 사이의 **실제 자동 연결이 없다**.

## 3. 왜 아직 N회 자동 육성을 시작하지 않는가

현재 사용자가 먼저 정할 수 있는 것은 회차·각질·횟수뿐이다. R44 세션의 필수 캐릭터 ID, 지원 카드 덱 ID, 계승 인자/부모 ID, 한국 서버 패치 정보, TP 상태 및 실제 게임 시작 화면은 검증되지 않았다.

이 정보를 임의 값으로 채워 세션을 자동 생성하면 잘못된 캐릭터/덱/육성 횟수로 반복할 위험이 있다. 따라서 지금은 **계획만 저장하고, 실게임 검수에 기반한 세션 파일이 존재할 때만 진행 기록을 표시한다.** GameTora 또는 일본 R13 공략 데이터는 세션의 실제 육성 완료 증거가 아니다.

## 4. 앞으로의 개발 순서

- R45 이후 R46: 기존 R38 레이스/터커 외출 판단, R40~R42 턴 효율·스킬/이벤트 판단을 **검수된 행동 후보별 하나의 읽기 전용 추천 흐름**에 통합하고, 판단 근거가 부족하면 추천을 보류한다.
- R47: R15 학습 데이터 출처/검수·훈련/검증 분리·롤백·이미지 정리 원칙과 R40 구조화 턴 기록을 연결한다.
- 게임 실행 가능 시: 실제 한국 클라이언트 화면에서 캐릭터/덱/부모/TP/이벤트/턴/완료 화면을 확인한 뒤 R44 세션 생성/갱신을 연결하고, 그때만 자동 입력 기능을 별도로 검증한다.

**R45 결과는 소스 구현 및 정적 검토 단계다. 전체 테스트·Windows 검증·실게임 동작 성공을 주장하지 않는다.**
