# R23 오프라인 검사·첫 실PC 진단

## 목적

R22에서 수집할 실제 게임의 한 턴 훈련 5종 캡처를 **손상/중복 검사 → 숫자 OCR 후보 → 사람 검수 → 조건부 비교** 순서로 다룬다. 실전 녹화 영상 또는 캡처만으로 누른 행동을 최적 행동으로 취급하지 않는다.

## 구조

- `offline_replay_r23.py`: 재생 목록 스키마, 같은 디렉터리 내 파일만 허용, SHA-256·중복·캡처 크기 검증, R22 OCR 호출, 읽기 실패 표시.
- `offline_replay_ui_r23.py`: 합성 샘플 실행, 사용자가 준비한 한 턴 캡처 5장/ROI 파일 복사, 이미지 조회, OCR 수치 확인, R22의 조건부 훈련 비교 사용. 자동 클릭 없음.
- `preflight_r23.py`: 운영체제·OCR·이미지 매칭·OCR 보정·장면/훈련 버튼 기준·게임 창 감지의 **설치 상태만** 로컬 점검. 개인정보·제목·파일 경로를 보고서에서 제외.
- `R23_먼저읽기.txt`: 실PC 테스트 순서와 차단 조건.

## 재생 목록

```json
{
  "schema":"uma_training_replay_r23_v1",
  "scenario":"island_post_patch_v1",
  "source_type":"local_unverified",
  "turn":"주니어급 7월 전반",
  "roi_profile":"r22_training_preview_rois.json",
  "captures":[
    {"choice":"스피드","image":"training_1.png","sha256":"<sha256 of training_1.png>"}
  ]
}
```

위 JSON은 예시 문서이며 `<sha256 ...>`은 실제 입력 가능한 값이 아니다. 도구가 만드는 목록에는 실제 SHA-256이 자동 기록된다. 출처 유형은 `synthetic_test` 또는 `local_unverified`만 허용한다. 그 이상의 검증 표시는 사용자 확인과 별도 증거 절차가 필요하다.

## 판단 및 실패 차단

1. 손상/변조/중복 캡처, 지원되지 않는 시나리오, 외부 경로·심볼릭 링크 참조를 차단.
2. 해상도 비율이 저장된 ROI와 3% 이상 다르면 OCR 사용 불가로 표시.
3. OCR 미설치, 저신뢰도, 읽기 실패 시 빈칸을 유지.
4. 일반 훈련 5종의 필수 검수 항목(스탯 5종, 스킬 Pt, 실패율, 체력 변화)이 충족되지 않으면 비교 보류.
5. 티켓 보유 시 섬 훈련이 필수 비교 대상으로 추가되므로 그 값이 없으면 비교 보류.
6. 자료의 출처가 합성이든 실제 게임 캡처든 검수 버튼과 인식 엔진이 자동으로 ML 정답 또는 최적 행동을 생성하지 않음.
7. R22에서 보인 기존 장면 인식·훈련 버튼 템플릿은 재사용하되 실제 한국 서버 화면의 인식률은 아직 확인되지 않음.

## 검증 범위

- Python 자동 단위 테스트 및 기존 기능 전체 회귀 테스트.
- Linux 가상 화면에서 R23 UI 표시·샘플 재생·수동 확인 흐름 테스트.
- 합성 이미지의 OCR 후보 확인(실게임 정밀도 아님).
- Windows 설치형 EXE 빌드 설정 정적 확인. 실제 Windows 실행 및 한국 서버 연동은 보류.

## 향후 시나리오 확장

현재는 `island_post_patch_v1` 시나리오만 활성화. 새 시나리오는 자체 ROI·화면 클래스·추가 항목 어댑터를 구성하고, 공통 이미지 해시 검증·검수·ML 분리 규칙은 재사용한다. 시나리오별 미확인 수치를 공통 모델에 섞지 않는다.
