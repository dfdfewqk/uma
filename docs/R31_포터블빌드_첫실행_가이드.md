# R31 — 포터블 우선 Windows 첫 빌드 안내

## 처음 빌드

1. https://github.com/dfdfewqk/uma/actions/workflows/windows-exe.yml 접속.
2. Run workflow → main → `build_installer=false`, `publish_release=false` 선택.
3. 정상 완료 시 Actions Artifacts의 `UmaTrainerKR-R31-Windows-Verified`를 다운로드.
4. `portable/UmaTrainerKR-Portable-v0.31.1.zip` 압축 해제. 별도 설치 없이 `UmaTrainerKR_Companion.exe` 실행.
5. 게임을 실행하기 전 진단 창을 확인. Tesseract OCR 설치가 별도로 필요할 수 있음.

## 문제 발생 시

- 빨간 빌드 표시: 실패한 스텝명과 로그를 보존한 다음 원인 수정. 실패한 빌드를 성공으로 표시하거나 릴리스하지 않음.
- 성공 후 ZIP이 없음: Artifacts 이름과 `portable/` 경로 확인.
- Windows 실행 경고/동작 실패: EXE의 자체검사 JSON과 실행 오류 확인. 패키징 검사가 한국 서버 동작을 보장하지는 않음.
- 설치형 실행파일이 필요할 때만 `build_installer=true`. 설치검사까지 추가됨.
- 사용자에게 배포할 때는 실Windows 결과를 확인하고 **새 수동 실행에서** `publish_release=true`로 공개. 동일 태그 재발행 금지.

## 안전 기준

- GitHub에 푸시만 해도 자동 빌드/출시는 되지 않음.
- 기본 동작은 게임 조작을 하지 않음.
- 업데이트는 사용자가 승인하면 SHA-256 체크 후 새 폴더에 풀고 실행. 기존 기록과 프로그램 보존.
- Windows 및 한국 서버 첫 테스트 결과는 아직 나오지 않음.

## R31.1 Windows 시작 오류 수정 (0.31.1)

- 0.31.0 빌드는 컴파일·자체검사를 통과했지만 실제 Companion GUI 시작에서 시나리오 설정 파일 누락으로 FileNotFoundError가 발생했다. 해당 ZIP은 실사용 검증에 실패했다.
- 원인: Companion과 Preflight EXE 패키징 과정에서 `scenario_policies/island_post_patch_v1.json` 미포함, 자체검사 필수 파일 목록도 불완전했다.
- R31.1은 4개 EXE 필수 설정 파일을 모두 등록하고 GitHub Actions·전체 수동 빌드·실시간 도우미 수동 빌드를 일치시킨다.
- 기존의 조기 `--self-check-report` 검증 외에, 모든 GUI 진입점 모듈 import 이후/Tk 생성 이전에 `--startup-check-report`를 검사하는 Windows 실파일 테스트를 추가했다. 어느 하나라도 실패하면 ZIP 검증·업로드를 차단한다.
- 배포 ZIP은 반드시 `UmaTrainerKR-Portable-v0.31.1.zip`을 확인한다. 이미 다운로드한 0.31.0 EXE는 사용하지 않는다.
- **빌드와 GUI import 성공은 전체 GUI 이벤트 루프·게임 화면 인식 성공 증명이 아니다.** 최종적인 첫 실행과 실게임 동작은 Windows PC에서 별도 확인이 필요하다.
