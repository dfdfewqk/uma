# Uma Trainer KR R17 — ML 연구 모델 등록부·버전 비교·실전 결과 검수

개발일: 2026-10-15 · 범위: R16 행동 모방 모델과 후속 실전 결과 라벨 준비

## 정직한 기능 한계
- R16 모델은 실제 플레이어 **행동 모방** 모델이지, 최적 육성 선택·챔미 승률·리오히 점수·고점 달성/도축 확률을 예측하는 모델이 **아니다**.
- R17의 **연구용 기준 모델**(champion)은 이전 모델과 비교하기 위한 연구 관리 항목으로만 사용한다. 기존 훈련 추천/자동 육성에 연결하지 않는다.
- 실제 검수된 일본 영상 턴, 한국 서버 실게임 OCR 검증, 실제 모델 학습 데이터는 **0건**이다. 기능 시험은 전부 가상의 임시 fixture에서 수행했다.
- 사용자 수동 검수가 증거의 진위나 실제 게임 화면의 진실성을 자동으로 증명하지는 않는다.

## 모델 관리 구조
- `model_registry_r17.py`: 로컬 `%LOCALAPPDATA%/UmaTrainerKR/r17_models/` 또는 홈 디렉터리 폴더에 R16의 *검증된 JSON* 모델을 ID별 읽기 전용 스냅샷으로 등록한다.
- 범위 구분 키: `scenario_id / server / patch_version / event` 4개가 모두 동일해야 한다. 서로 다른 시나리오·패치·대회 모델은 비교/복원/승격할 수 없다.
- 동일 데이터셋 ID·특징 스키마인 모델만 비교한다. 데이터셋이 다르면 새로운 공통 독립 홀드아웃 체계가 필요한데 현재 구현하지 않았으므로 자동 비교를 **보류**한다.
- 비교 대상은 R15에서 검수된 **같은 validation 분할**이다. 최종 시험용 `test`는 승격 판단에 이용하지 않는다. 학습 분할 `train`도 승격 지표에 사용하지 않는다.
- 기준: 사람 행동 모방 정확도가 다수 행동 baseline 이상이어야 함. 기존 기준 모델이 있다면 검증 log-loss가 0.005 이상 개선되고, 정확도 및 macro F1도 0.01보다 크게 떨어지지 않아야 연구 기준 승격 허용. 수치는 엔지니어링 안전 규칙이며 실제 승률 최적화 목표가 아님.
- 승격과 복원은 별도 명시적 UI 버튼이 있어야 실행된다. 모델은 덮어쓰지 않고, 파일 해시/등록부 해시 검사 후 이력을 남긴다. **실전 자동 적용/다운로드/서버 전송은 없음.**
- 같은 학습 데이터 반복 평가 시 validation 과적합 위험이 있다. 데이터셋이 달라지면 별도 분할된 최신 자료와 최종 untouched test 검증을 설계한 후에만 비교 기능을 확장해야 한다.

## 실전 결과 데이터 수집
- `result_labels_r17.py`: 기존 `runs.sqlite3`에서 이미 완료/중단 상태로 저장한 세션을 선택하고 결과 화면 이미지·서버·패치·출처ID·검수 근거를 등록한다. 검수 메타데이터는 기존 DB와 별개인 `r17_outcome_reviews.sqlite3`에 저장한다.
- 캡처 이미지의 내용 진위를 완전히 확인하는 자동 모델은 아직 없으며, 사용자 수동 검수가 전제이다. 원본 세션/결과/턴 수 또는 증거 이미지가 바뀌면 검수가 **무효**가 된다.
- 결과 레코드 구분: `completed` (육성 완주), `censored_abandoned` (도축/중단; 달성했을 최종 결과는 관측되지 않음). **도축을 완주 실패라는 지도 라벨로 사용 금지.**
- 챔미 대회 실적(`matches`, `wins`)과 리오히 점수(`loh_points`)는 선택적으로 기록하되 값이 검증되지 않았다면 비워 둔다. 육성 완주와 실제 경기 승리는 다른 사실이다.
- 익명화된 `uma-r17-result-observation-v1` JSONL로 내보내며 `direct_ml_training_allowed: false`가 기본이다. 본육성 전 행동의 정답 또는 승률/도축 확률 예측 학습 라벨로 자동 사용하지 않는다.
- 결과 캡처에는 개인정보 및 게임 사용자 정보가 들어 있을 수 있다. 외부 공유 금지, 사용권과 제3자 자료 이용 조건을 확인해야 한다.

## 새 시나리오를 추가할 때
1. `scenario_policies/`와 `scenario_features_r15.py`에 새 규칙 및 사전 행동 특징을 분리해 구현한다.
2. `scenario_ml_features_r16.py`에 시나리오별 ML 특징을 추가하되 공통 특징 의미를 변경하지 않는다. 변경 시 특징 스키마를 올려 모델 혼용을 막는다.
3. `scenario_id`, `server`, `patch_version`, `event` 범위를 반드시 기록하고, 다른 범위는 별도 데이터·학습 모델·등록부 scope로 분리한다.
4. R15의 증거 검수→데이터 분리→R16 행동 모방 연구→R17 동일 validation 비교→명시적 연구 챔피언 선택 순서를 유지한다.
5. 새 시나리오 실제 완주·중단·대회 실적은 R17 결과 모듈에서 독립 증거로 축적하되, 충분한 자료와 편향/검열 처리가 완료되기 전까지 최적 육성 AI로 학습하지 않는다.

## 실행 / 검증 / 미완료
- 실행: `python app.py` → **⑱ R17 모델·결과** 탭. R16 연구 모델을 먼저 저장하고 R15 검수 JSONL 내보내기가 있어야 연구용 비교가 가능하다.
- 현재 실제 검수된 학습 자료가 **0건**이므로 R17 모델 등록부는 처음에 비어 있고 연구 챔피언도 없다.
- 테스트: `python -m unittest discover -s tests -v`. R17 새 테스트는 모델 등록/불량 모델 방지/동일 검증·누출 차단/원상 복원, 중단 데이터 검열/경기 자료/증거 변경 감사 등을 검증한다.
- Windows EXE/설치파일은 GitHub Actions **수동 workflow_dispatch** 빌드 설정만 준비. 실제 Windows 빌드 및 한국 서버 OCR 테스트는 미완료이다.
- 권장 다음 단계: R18에서 **다중 데이터셋 통합·단계별 결과 수집, 실전 경기 코스/각질/스킬 발동 기록 스키마, 검증된 중도 포기 표본 편향 처리**를 개발하고, 실제 실전 캡처로 정확도를 검증한다.
