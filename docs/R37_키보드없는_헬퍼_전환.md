# Uma Trainer KR R37 — 키보드 입력 없는 Companion 헬퍼

## 최종 사용자 경험 (설계 목표)

사용자는 게임 창에서 **훈련, 휴식, 외출, 레이스, 이벤트 선택지**를 직접 클릭한다. 헬퍼는 읽기 전용으로 화면을 관측하고 후보 행동과 이유를 표시한다. 플레이 도중 숫자·턴·인연도·선택 결과를 타이핑하지 않는다. 게임에 자동 클릭이나 키보드 입력도 보내지 않는다.

## 이번 버전 v0.31.3에서 실제 구현한 것

1. Companion을 열면 화면 분석을 자동 시작한다. 메인 화면은 **지금 할 일**, 화면 인식 상태, 자동 OCR 수치 후보를 먼저 보여 준다.
2. 수동 입력·자료 내보내기·R22/R23 점검·업데이트·상세 설정은 기본 화면에서 감추고 **설정·개발자 점검 보기** 버튼을 눌러야 펼쳐지도록 정리했다. 기본 화면에는 타이핑 필드가 없다.
3. **화면 분석 일시 정지 / 다시 시작** 버튼을 제공한다. 정지하면 이전 화면의 OCR 후보·검수 추천·게임 위 표시를 지운다. 사용자 타이핑이나 게임 자동 클릭 없이 작동한다.
4. 게임 화면을 자동으로 캡처하되, 기존 R20 고유 앵커와 R21 버튼 패턴이 충분히 검증된 경우에만 화면 유형·버튼 위치를 보여 준다.
5. 실제 R28 검수 추천과 현재 화면의 위치가 일치할 때만 **해당 훈련 클릭 후보**를 표시한다. 화면이 전환되거나 게임 포커스가 없거나 인식이 불확실하면 임의의 추천을 만들지 않는다. 지금 R28은 훈련 전용이며 휴식·외출·레이스 최적 판단 근거가 아니다.
6. 화면 OCR로 얻은 체력 **25 이하 숫자 후보가 두 프레임 연속 일치한 경우에만** `체력 낮음 · 휴식·외출 검토`를 표시한다. 이것은 OCR 미검증 후보에 따른 주의 표시이며, 휴식/외출이 검증된 최적 행동이라는 뜻이 아니다. 화면 변경·포커스 상실 시 폐기한다.
7. 이벤트·스킬·시설 화면의 효과를 아직 읽을 수 없으면 장면만 안내하고 추천을 보류한다. 사용자에게 선택지 내용을 타이핑하라고 요구하지 않는다.

## 중요한 한계

**이번 릴리스는 기본 헬퍼의 UI와 읽기 전용 상태 관리 개선이지, 게임 화면 OCR의 완성이 아니다.** 현재 R20/21 템플릿과 숫자 OCR에는 실제 한국 서버 화면 기반의 검증/프로필이 필요하다. 아직 자동으로 각 훈련의 효과/성공률·시설·우정·섬 티켓/레이스 목표·이벤트 효과를 완전 판독하지 못하며, 전체 행동의 최적성을 판단하지 않는다. 한국 서버에서 검증되지 않은 정보를 자동 선택·자동 추천으로 가장하지 않는다.

다음 단계는 실제 PC 클라이언트에서 확보한 화면 자료를 기준으로 **훈련 5종의 상승량, 체력 소모, 인연·시설·티켓·이벤트 텍스트를 자동 추출해 R6/R35의 입력 경로를 대체**하는 것이다. 앱 기본 모드에서는 수동 글자 입력으로 이를 대신하지 않는다.

## 테스트와 배포 안전

- `helper_view_r37.py`: 순수 판정/표시 정책, 불확실한 관측에서 추천 거부, 보류/체력 경고
- `helper_smoke_r37.py`: Xvfb에서 실제 Companion Tk 화면 생성 → 개발자 도구 숨김 → 기본 화면 타이핑 필드 개수 검사 → 정지/재개 → 개발 도구 펼침/접힘 확인
- `tests/test_helper_r37.py`: 합성 입력 경고·상태 전환·정확한 R28 위치 제한·오류 보고/개인정보 배제 등 회귀 테스트
- `scripts/validate_helper_r37.py`: Linux 실제 Tk 검사 결과를 검증하고, 변경/누락되면 Windows 패키징 중단
- `windows-exe.yml`: `linux-gui-preflight`에서 R36 전체 연구용 Tk GUI와 R37 Companion 두 가지를 검증한 뒤 Windows EXE 4종을 만들고 시작 모듈/자산 검사. **Windows 실물 GUI 실행이나 실게임 OCR 검증은 보증하지 않음**.
- 원본 R31.1/R36 v0.31.2, 로컬 사용자 기록, R6 휴리스틱, ML 데이터/모델 모두 그대로 보존.
- 수동 workflow_dispatch만 유지, 출시 및 설치파일 제작 기본 OFF.
- 새 0.31.3 빌드가 실제로 성공한 것은 별도의 GitHub Actions 실행·아티팩트 확인 후에만 선언.
