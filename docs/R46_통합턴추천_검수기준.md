# Uma Trainer KR R46 — 턴별 추천 엔진 통합 (소스 단계)

기준: R45 main `982a69243891c7cf263fcb1080b292b85ac7e06c`. 기존 파일·사용자 육성 기록·기존 게임 창 감시·R28 훈련 힌트·학습 데이터/일본 연구 원본은 보존한다. **실제 게임을 실행하거나 Windows EXE/배포/전체 테스트를 진행하지 않는다.**

## 1. 통합 설계

`unified_advisor_r46.py`는 R38 캐릭터 목표 달력과 터커 외출 연구 안내, R40 턴 행동 점수, R42 두 화면 안정성 검사/스킬 Pt 예산 검사를 **읽기 전용 단일 진입점**으로 묶는다. 자동 버튼 클릭·유료 재화·실제 ML 학습과 분리한다. 결과는 한 번에 한 행동 후보, 짧은 이유, 참고 메모, 검수된 경우에만 생성 가능한 화면 전환 대기용 제안 티켓으로 나뉜다. 모든 응답의 `game_input_allowed=False` 및 `optimality_verified=False`는 의도적인 설계다.

- **훈련/일반 레이스/휴식/외출**: 전부 현재 화면에 존재하고 행동별 수치·체력·우정·스킬 Pt·실패율이 검수된 경우에만 기존 R40 연구용 휴리스틱으로 후보를 비교한다. 복수 선택지가 없거나 보상이 미검증이면 추천하지 않는다. 이 점수는 승률 예측값이 아니다.
- **캐릭터 필수 레이스**: R38의 `CharacterCalendar`가 실제 한국 서버, 정확한 캐릭터·의상·패치·시나리오와 일치하고 `complete=True`이며 화면의 해당 턴 목표가 검수됐을 때만 우선 안내한다. ‘목표 레이스’ 버튼이 현재 화면에 정확하게 존재하지 않으면 강제로 표시하지 않는다. 불완전한 달력/미확인 경기 일정은 보류한다.
- **다음 턴 특기율**: 검수된 다음 턴 필수 레이스가 확인되면 다음 턴 훈련 이득으로 합산하지 않는다. 서로 다른 출처의 레이스 정보가 충돌하면 추천을 보류한다. 다음 턴 레이스 여부를 확인하지 못했고 후보가 일회성 버프를 포함하면 보류한다.
- **터커 외출**: R38 일본 2025·SSR 최대돌파 연구는 참고 메모로만 표시한다. 한국 서버 실제 회복량·단계/링크 여부가 검증되지 않은 일본 수치로 행동 점수를 계산하지 않는다.
- **시설/섬 행동**: R40의 `TurnOption`은 발전 Pt/티켓 등의 재화 소모와 이후 기회비용을 충분히 표현하지 못한다. R46은 비용을 무시하고 이 행동을 최고 효율로 고르지 않도록 **해당 후보가 섞인 장면의 통합 순위를 보류**한다. 이후 자원 장부/선택 결과를 검증한 뒤 비교식에 반영한다.
- **서포트 카드 이벤트**: R40 한국 서버 카탈로그에서 동일 카드 ID·카드 버전·패치·이벤트 단계·모든 선택지에 대해 미리보기 및 실제 결과 검수 데이터가 존재하고, 목표 금색 스킬로 이어지는 경로가 유일할 때만 그 선택지를 후보로 표시한다. 다른 자료/일본 자료, 미확인 분기는 보류한다. 보통 이벤트의 스탯/체력 효율 가중치는 아직 미개발이므로 ‘가장 좋은 선택’이라고 단정하지 않는다.
- **스킬 구매**: R42 예산 검사와 현재 레이스 거리·각질·마장·보유 스킬 Pt·스킬 구매 화면 검수 결과를 이용한다. 동일 레이스 연속 2패 이후 남은 재도전이 있을 때만 최대 2개 구매 후보를 고려한다. 한 번에 화면에 있는 첫 후보만 제안하고, 실제 구입은 하지 않는다. 마지막 턴의 전체 챔미/리오히용 최종 스킬 최적화는 아직 미구현이다.
- **중복 행동**: R42 `IntentGate`와 결합해 같은 장면·선택지/검수 보상을 연속 두 번 확인해야 한 번만 추천하며, 다음 장면을 검수해 확인할 때까지 다른 행동 제안을 보류한다. 같은 시점에 스탯/목표/보상이 바뀌어도 기존 후보의 상태를 재사용하지 않는다.

## 2. 실제 Companion 연결 범위

`companion.py`에 R46 통합 추천 준비 현황을 추가한다. 현재 R37~R45의 실시간 파이프라인은 대부분 **OCR 후보 수치/버튼 텍스트**만 제공하고, 개별 행동의 검수된 효과·서포트 위치/인연·시설 소모 자원까지 전달하지 못한다. 그래서 R46은 이 OCR 후보를 자동으로 검증 완료한 행동으로 취급하지 않는다. 기존 R28 힌트는 보존하며, R46 상태는 ‘어떤 검수가 더 필요한지’를 보여주는 별도 안내로 표시한다. 이 상태 표시는 **이미 게임에서 매 턴 최적 행동을 추천한다는 뜻이 아니다**.

새 진입점 `UnifiedAdvisor.evaluate(DecisionInput)`은 추후 실제 한국 서버의 검수된 `ObservedFrame`, `TurnEvidence`, `ScreenTurn` 등을 받을 때 사용한다. 한국 서버 게임 입력·마우스 클릭은 아직 연결하지 않는다.

## 3. 회귀 검증 코드만 작성

`tests/test_unified_advisor_r46.py`에는 16개 검증 시나리오를 작성했다. R40 훈련 점수 연결, 두 화면 검수/중복 후보 차단, 필수 레이스 우선, 다음 턴 충돌, 미확인 특기율, 검수된 금색 스킬 연속 분기, 이벤트 미확인 차단, 스킬 Pt/각질 예산, 일본 터커 안내의 참고용 제한, 시설 자원 비용 누락 차단을 점검하도록 설계했다. **이번에는 실행하지 않았다.** 통합 코드·테스트의 정상 실행 여부는 향후 소스 전용 전체 검사로 검증해야 한다.

## 4. 다음 단계 R47과 이후 실게임 준비

R47에서는 R15 ML 검수 데이터와 R40/43 턴 기록의 출처, 패치·시나리오 격리, 모호한 OCR 배제, 학습/검증 분리, 중복 결과·회차 정리 및 이전 정책 복원 기반을 연결한다. 실제 게임이 가능할 때는 화면 검수 자료 수집 → 행동 보상/시설 자원 검수 → 실시간 R46 입력 어댑터와 추천 효과 확인 → 별도 게임 입력 안전 조작 → 실제 반복 육성 검증 순서로 진행한다.
