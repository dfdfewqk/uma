# Uma Trainer KR R11 — 실전 목표 격차 분석 (2026-10-15)

## 범위

- 대상은 **한국 서버 PC / 무인도 / 챔피언스 미팅 또는 리그 오브 히어로즈** 육성 분석.
- 이전 R1~R10 코드·자료·SQLite를 삭제/초기화하지 않고 `goal_tracker_r11.py`, `goal_ui_r11.py`, `tests/test_goal_tracker_r11.py`를 추가.
- 프로필의 목표 스탯과 현재 스탯 차이 및 남은 턴당 필요한 **산술 평균** 계산. 이것은 미래 상승량/성공률 예측이 아니다.
- 필수 스킬을 미확보/힌트확보/획득완료/미확인으로 분리. 미획득 스킬의 *사용자가 확인한 유효 Pt 비용* 합계가 완전히 알려진 경우만 즉시 구매 시 부족 Pt를 계산한다.
- 6개 시설 목표 Lv와 현재 Lv를 비교하며 목표가 비어 있으면 미확인 처리. 시설 강화 분기·건설 코스트에 따른 미래 성공 여부는 R7의 검수된 구조 규칙을 별도로 보아야 한다.
- 평가회 목표 발전 Pt + 남은 턴을 함께 넣었을 때만 격차를 산술 비교.
- 섬 티켓 수량과 수령 시점 미확인을 구분. 티켓 사용 자동 결정 없음.
- R3 로컬 기록 기반 과거 증감 중앙값은 **같은 육성 세션 / 동일 프로필 / 마지막 저장 상태 = 현재 상태 / 연속 기록 5개 이상**일 때만 노출. 관측치는 인과 효과가 아니고 실전 검증 표본이 아니다.
- JSON 저장 시 검수 입력과 턴 상태 해시 대조. 입력 수정/새 턴 후 오래된 분석의 저장 차단. 원본 스크린샷의 로컬 경로는 출력에서 제외.

## 자료 검증 제한

- 실제 일본 플레이 영상에서 턴별 실측 검증 **0건** (R10 상태 유지).
- 한국 서버 실화면 OCR 검증 **0건**.
- 시설별 공식 스탯 배율 검증 없음, 승률 예측 ML 모델 없음, 자동 도축 및 게임 자동 입력 없음.
- `target_stats` 기본 수치는 UI 예시이며, 대회별 최적 목표가 아님.
- 시설 목표 Lv 전체 입력 및 스킬 목록 확인이 없으면 실전 육성 목표 달성 판정은 **보류**.
- `필수 스킬 획득 완료`라는 데이터는 플레이어의 직접 확인 상태이며 스킬의 해당 코스 실효성을 보증하지 않음.
- QA는 합성 데이터로 실시, 기존 연구 검수 CSV에 섞지 않음.

## 테스트 절차

1. `python -m unittest discover -s tests -q`로 전체 회귀 테스트.
2. GUI 통합: 임시 HOME / Xvfb로 `app.UmaApp()` 기동, R11 탭 선택 → 스킬/시설/평가회 입력 → 분석 및 JSON 저장, 입력 변경 후 저장 차단 확인.
3. 이전 V0.10 `.sqlite3` 파일에 새 열 추가/삭제 없음. 기존 DB 유지.
4. Windows EXE/Setup은 GitHub 수동 워크플로만 준비. 실제 Windows 빌드 및 우마무스메 연동 검증 전.

- 실제 PC 테스트 시 스킬 구매 화면/스킬 힌트 가격 할인, 시설 루트, 평가회 수치를 확인해 R11 수동 입력 값 검증.

## 목표 템플릿 관리

- `목표 저장` 버튼은 현재 경기장·대회·각질·시나리오·목표 스탯에 한정된 목표 템플릿(JSON)을 저장한다.
- `목표 불러오기`는 조건이 정확히 같은 경우만 허용한다. 실수로 다른 대회 조건을 불러오는 것을 방지한다.
- 불러온 파일의 필수 스킬 **검수 완료 여부는 계승되지 않는다**. 사용자가 다시 확인해야 한다.
- 평가회까지의 남은 턴은 매번 달라지므로 **불러올 때 항상 빈칸**으로 처리한다.
