# R48 실게임 훈련 미리보기 비교 — 실제 사용 및 검증 한계

## 해결 목표
2026-10-16 한국 서버 실제 게임 화면에서 게임 창 감지는 성공했으나 훈련을 전혀 추천하지 못했다. 원인은 R20 장면 특징 템플릿과 R21 버튼 패턴이 사전 등록되지 않았고, R46 엔진에 개별 훈련의 스탯/인연/실패/스킬Pt 보상을 수집해 전달하는 실시간 어댑터가 없었기 때문이다. **게임 창 크기나 위치 문제를 반복 수정해서 해결할 사항이 아니다.**

## 새 로컬 관측 방식
`training_preview_r48.py`는 사용자 녹화 영상의 한국 서버 세로형 UI를 기준으로, 노란 결정 리본이 있는 현재 선택 훈련을 확인한다. 각 선택지 화면의 스탯 패널 위 `+숫자`를 **로컬 Tesseract**로 읽는다. 게임에서 스피드/스태미나/파워/근성/지능을 3~5초씩 차례로 열면 같은 게임 턴의 관측값을 모은다. 한 선택지 보상은 동일 OCR 결과가 2회 이상 읽혀야 수집한다. 기존 턴의 스탯 기준줄 또는 창/화면 크기가 바뀌면 모아 둔 후보를 없앤다. 보상을 알 수 없으면 0으로 대체하지 않는다.

## 표시 및 제한
한 턴의 5개 훈련이 모두 수집되면 화면에서 실제로 표시된 **스탯 상승량 합계**만으로 우선 후보를 보여준다. 근접 점수면 보류한다. 결과는 **'훈련 · 잠정 후보'** 이며 최적 효율 보장이 아니다. R46의 종합 판단(인연, 우정, 스킬 Pt, 실패 위험, 터커 외출, 시설 발전 Pt, 필수 레이스)은 실제 장면에서 현재 데이터를 읽는 연결이 아직 없어 섞지 않는다. OCR 후보를 검수 완료 데이터로 승격시키지 않고, 학습/저장 원본이나 자동 클릭을 만들지 않는다. 화면 크기/게임 스킨이 달라 검출 실패하면 그 사실을 표시한다.

## 패키지
Windows Actions는 Python 소스+Xvfb Tk GUI 검사 후 설치형이 아닌 네 가지 EXE를 만든다. 이번 Companion에 숫자 OCR 실행파일과 eng.traineddata를 포함해 PC에서 별도 OCR 설치 부담을 줄인다. 자체 시작/무결성 검증이 통과하기 전에는 최종 성공 아티팩트 링크를 제공하지 않는다.

## 현장 점검
1. 게임 화면에서 훈련으로 들어간다.
2. 도우미 상단의 '훈련 미리보기 X/5'가 갱신되는지 확인한다. 5개를 모두 훑되 마지막 '훈련 결정'은 누르지 않는다.
3. 5/5가 됐을 때 표시된 수치가 실제 +숫자와 일치하는지 검수한다.
4. 0/5에서 멈추면 오탐/미탐 위치 및 해상도 문제, 특정 훈련만 누락되면 OCR 문제로 분리해 수정한다.

### 검증 구분
CI 테스트는 모의 화면과 창 전환 규칙의 회귀 검사이며 **실제 KR 게임 장면에 대한 OCR 성공률이나 임시 추천 정확도를 증명하지 않는다.** 실제 게임에서 테스트할 때 이 오류를 피하려면 OCR 검증 로그/캡처가 추가로 필요하다. 오프라인 숫자 OCR만 우선하는 R48은 R47과 R46의 다른 시스템과 사용자 데이터를 보존한다.
