# R57 — 실험적 자동 훈련 클릭 후 전환 확인

기준 R56 `0f2c6257030a9b10a2f8b8965c921a1c7d6513d9`, R51 백업 브랜치 보존.

## 문제 확인
- R49 TrainingTour의 on_click_result는 Windows 포인터에서 True를 반환한 순간 commits를 증가시켰다. 이는 UI 클릭 *전송*일 뿐 실제 게임의 훈련 완료 증거가 아니다.
- R49는 미리보기 버튼 클릭 후 1회에 선택된 UI와 OCR을 확인했으며, 훈련 확인 클릭 뒤 baseline 지문만 바뀌면 새 턴으로 오인해 다음 클릭을 진행할 가능성이 있었다.

## 보강
1. 새 `training_transition_r57.TrainingClickGuard`는 훈련 미리보기/실행 클릭마다 전경 HWND·사각형·클릭 전 턴 지문·목표 훈련·시간을 잠근다.
2. 미리보기 버튼을 누른 뒤 실제 선택 훈련 표식과 해당 R48 OCR 수집 정보가 동일 턴에서 두 번 연속 관측돼야 다른 미리보기 클릭을 허용한다. 미확인/충돌/시한 초과 시 자동 입력 중단.
3. 훈련 실행 클릭은 다음 화면/새 baseline 후보가 두 번 확인되더라도 게임 내 **턴 진행·보상 성공을 증명하지 않는다**. 자동 실행을 멈추고 검수 요구 상태를 표시한다. 기존 실험 클릭은 사용자의 명시적 선택 후에만 가능.
4. 포인터의 실제 입력 전 게임 활성 창/크기/씬/선택 대상 재검사는 유지. 유료 TP, 주얼, 비훈련 자동 입력 허용을 추가하지 않음.
5. R49 포인터가 보낸 클릭을 실제 완료 횟수로 증가시키지 않도록 잘못된 집계를 수정.
6. 자동 실행 정지/일시 정지/게임 창 또는 목표 변경 시 대기 중인 확인 게이트 폐기.

## 테스트
- 새 독립 모듈 8개 단위 테스트: 로컬 Python에서 실행·통과.
- 전체 저장소 회귀테스트, Windows 실제 게임 입력, OCR/인게임 턴 성공 검증은 수행하지 않음.
- 새 Windows EXE 빌드/배포는 시행하지 않음.

## 사용자에게 필요한 후속 자료
실제 한국 서버의 훈련 확인 이후 화면 전환(애니메이션·이벤트·다음 턴·보상 표시) 영상/화면, 턴 번호 및 현재 스탯 전후 검수 자료가 있어야 실제 후속 턴까지 안전하게 자동 진행할 수 있다.
