Uma Trainer KR R25 — Windows 설치파일 생성·실행 검증 단계

[핵심 변경]
R24의 훈련 판단/영상·OCR/게임 옆 도우미 기능을 보존했습니다.
새 연구용 기능을 늘리는 대신 Windows에서 실행파일이 실제 시작되고 필요한 데이터가 포함되는지 검증하는 장치를 추가했습니다.

[R25에서 자동으로 검사할 것 — GitHub Actions의 Windows 러너에서 수동 실행할 경우]
1. 기존 코드 + 새 코드의 Python 테스트 실행
2. 사용자용/작업용 EXE 4개 생성
3. 각 EXE를 GUI 없이 자체 진단 모드로 직접 실행하여 코드 및 필수 자료 확인
4. 설치파일 생성
5. 임시 폴더에 설치 → 설치된 EXE 4개 존재 확인 및 자체 진단 실행 → 제거
6. EXE와 설치파일 SHA-256 체크섬 보고서 생성
7. 성공했을 때만 Actions 다운로드용 아티팩트 보관(Release 게시 안 함)

[중요] 지금 ZIP 안에는 이미 빌드된 Windows EXE가 없습니다.
현재 작업 환경에서는 Windows 전용 EXE/설치파일을 실행해 본 것이 아닙니다.
GitHub Actions 워크플로는 'Run workflow'를 눌러 직접 실행해야 합니다.
소스코드가 저장소에 업로드되지 않았다면 워크플로를 시작할 수 없습니다.

[프로그램 이용자에게 제공할 파일]
- UmaTrainerKR_Setup_0.25.0.exe : 전체 설치파일 (Windows 빌드 통과 시 생성)
- UmaTrainerKR_Companion.exe : 게임 옆 소형 도우미
- UmaTrainerKR_GameTest.exe : 현재 턴 훈련 5종 수동 검수
- UmaTrainerKR_Preflight.exe : 오프라인 OCR·첫 실행 환경 점검
- UmaTrainerKR.exe : 개발·상세 설정 및 연구 화면

[실제 한국 서버에서 테스트할 절차]
1. 창 모드로 게임을 실행하고 Companion을 열어 게임 창 인식 여부를 확인합니다.
2. Preflight에서 Tesseract OCR 설치 상태를 확인합니다. Tesseract는 배포 EXE에 자동 동봉되지 않습니다.
3. 게임 화면에서 스피드/스태미나/파워/근성/지능을 각각 선택하면서 GameTest에서 캡처합니다.
4. 각 숫자의 인식 결과를 게임과 눈으로 비교한 다음 검수합니다.
5. 서로 다른 메뉴·화면·턴으로 이동하면서 잘못된 수치/강조가 남지 않는지 확인합니다.
6. 개인 자료가 포함된 스크린샷과 진단 JSON은 외부 업로드 전에 직접 확인합니다.

[검증 구분]
- Python 자동 테스트 PASS = 소스 회귀 테스트 통과
- Windows EXE self-check PASS = EXE 시작과 포함된 자료 검증 통과
- Inno Setup 설치/제거 PASS = 설치 동작과 파일 존재 검증 통과
- 한국 서버 게임 연동 PASS = 실제 게임 화면 인식/표시 확인 (아직 미실시)
- ML 실전 승률 및 도축 모델 = 아직 검증 데이터 부족
- 자동 클릭 및 자동 육성 = 아직 미구현, 현재 검증 대상으로 포함하지 않음

[배포 정책]
- GitHub 자동 커밋, push-trigger, scheduled workflow, 자동 release 모두 금지
- 모델 성능은 검수된 데이터로 별도 검증하기 전까지 주장하지 않음
- R1~R24 원본과 사용자 로컬 SQLite/이미지/모델 기록을 삭제·이동하지 않음
